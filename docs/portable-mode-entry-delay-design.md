# 条件付き武器変更と進入待ち（未接続）

HP由来攻撃力の実編成検証で、ラプラス：アルティメットヒーローの通常／成長180秒がGPU変換時に拒否されました。134条件と旧130条件は検証できましたが、全136条件の成功ではありません。2条件を除外して母数を減らしません。

この武器変更は `full_charge_fire`・予熱5スタックで発動し、時間期限を持たず120発で終了します。元CPUの武器変更条件は通知時の発動条件であり、予熱を直後に除去しても変更状態は続きます。GPUにも発動条件・変更状態・発数終了の処理がありますが、アダプターの無期限条件付きモードのガードが残っています。

ガード1行だけを外した別コピーのアダプターで変換を試すと、次は `pack_mode` が進入待ちの未実装として拒否しました。GPUは一度も実行していません。本体の両ガードは保持しています。失敗記録は `portable-conditional-mode-candidate-compile-finding.json` です。

元の `_DELAYS` にはこのモードの `entry_delay=0.39` があり、変更状態を物理的に処理し始めた最初のtickから待ちます。発動した通知時刻から単純に0.39秒を足す処理ではありません。元 `_tick_weapon_change` は進入待ちを先に処理し、待ちが終わってから変更武器の弾倉と発射ループへ進みます。待ちの完了でチャージ状態をreadyへ戻し、チャージを無料で経過させません。`entry_reload` の速度補正付き待ちとは区別します。

共通実行器へ接続する前に、初回tickと発動の時刻差、0・正の待ち、進入待ち中の解除／切替／更新、チャージと連射、弾倉の初期化時刻、発数終了、待ちと有限期限の競合、再進入を元CPUで観測します。既存のpost-reload時計を転用して意味を変えず、必要な状態を明示し、生成初期化器を更新します。入力の未使用モード領域へ数量・有無を入れる場合は版と生入力検査も必要です。

まず別コピーで元CPUと一致させ、ラプラスの全効果を含む2実編成を確認してから本体へ採用します。その後に旧3539入力・旧134編成の保持、全体検査、短いCUDA検証、全検証・転送後の効率測定を行います。通常画面はCPUで、全キャラ認証は未完了です。
