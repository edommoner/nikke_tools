# 対象条件と親子の通知文脈

v74では、本体／追加の敵の条件を現在の評価対象へ接続します。CPUの対象条件は、明示された命中情報、または対象カウンターの完了対象を優先します。完了通知が命中情報を持たない死亡経路でも、完了時に捕捉した対象の種類・ID・世代を使います。照準の変更や同じIDの再出現によって、既に起きた通知の対象を付け替えません。対象が明示されていない場合は、既存の照準選択を使います。

CPUは既存の不変な `EventFrame` に対象ハンドルの参照を一つ加えます。命中情報と明示対象が矛盾する場合は拒否します。親の文脈を子が書き換えず、例外が発生しても元のイベントスタックへ戻します。上流の対象条件の式を、検査付きの変換で共通の参照口へ置き換えます。変更箇所が想定と異なる場合は起動時に拒否し、上流ソースを直接編集しません。

GPUは対象条件42・43と `TargetRef` を使います。既存の深さ32の同期実行器で、その通知の対象を保持します。命中数通知・対象カウンター完了通知と、関数呼び出しに相当する内部の継続フレームが対象を継承します。装填・回復・状態終了・スタック到達等の別通知は独立した文脈です。子の終了後は親の対象へ戻り、実行器を抜ける場合やエラー時にも入口の対象へ復元します。命中数と完了通知の継承規則はCPU/GPU共通の定義から生成します。

現在の論理条件では、本体と本体の物理部位が本体側、追加の敵が追加の敵側です。飛翔体や敵シールドを暗黙にどちらかへ分類しません。それらのカウンターと動的な対象条件の組み合わせは、共通の入力検査でコンパイル時と実行前に拒否します。GPUの通常計算は追加の敵の自律ルーティングをまだ受け付けず、対象が明示されていない場合のGPU照準先は本体です。追加の敵への自律照準とルーティングを接続する際に、この入口へ実際の選択対象を渡す必要があります。

GPUの部隊状態は1,219,104バイトです。対象ハンドル12バイトと配置上の余白により、v73から16バイト増えています。命令幅344語・キャラ入力169語は変えません。追加の敵が存在しないことが検証できる通常の世界では、条件を従来の定数条件へ特殊化し、既存187体の生成命令と武器入力を保ちます。

検証は同じ共通効果集合で、本体、部位、追加の敵の異なる出現世代を扱います。追加の敵は実際のHPプールへ計10ダメージを与え、命中数による完了と命中情報を持たない死亡時の完了の両方を発生させます。親の条件を満たした効果、別の文脈を使う子効果、親へ戻った後の後続効果、終了後の通常イベントを観測し、CPUと独立した期待値へ照合します。合計だけの照合ではなく、10時点の状態と実完了数を確認します。CPUの例外・明示対象の衝突・同じIDの別世代・照準との不一致も共通の単体検査で扱います。

同じ集合にHP減少とHP境界での回復を加えた2つ目のケースも使います。追加の敵を扱う親から、スタック到達・HP変化・回復・子から戻った後の処理を実際に発生させます。HP通知が古い子の文脈を引き継がず、親の追加の敵も失わないことを、能力値・HP復元・完了数で確認します。別のキャラ用に同じ行列を作る方法は使いません。

機能確認版は `research/ports/v74-target-context-native-stage` に保存しています。既存の発動順25ケースを再利用し、内部継続、HP変化、回復の再入、戦闘不能と復帰も確認しています。その後の効率化では、コンパイル済みの不変な定義に対象条件が存在するかを初期化時に調べ、存在しない場合の文脈配列の更新と復元を省きます。対象条件があれば、省略せず同じ同期処理を使います。

この接続だけで、命中先ごとのバフ保存や遅延ダメージの振り分けは完了しません。追加の敵に付ける効果の実体、対象の世代を持つ予約命中、自律照準と対象選択、実際の射撃単位と物理的な到達先は残っています。通常の召喚受付や `multi_hit` の受付は引き続き拒否し、残り16体の対応や全効果の完成を主張しません。

最終版はnative/PTX各2ケース、軽い共通検査95件、既存の発動順25ケース、敵数条件2ケース、混成10部隊が通過しています。所持装備と一時的な攻撃力変更、モード運用の有無・復元を含む通常APIでは、GPU単独・CPU照合付きGPU・CPUの部隊結果が一致しました。一時変更前後の合計は879,777,937と914,873,125です。以前の出現元13ケース／被弾・世界7件は、関連する世界・HPプール・被弾の9関数が同一であることを確認して再利用し、今回の再実行件数へ加えていません。

キャッシュなしの通常8候補APIは、機能確認版7,185.3275ms、省略処理の追加後7,413.2773msでした。単回比較であり、速度向上は確認していません。不要な文脈更新を減らすことと、全体の計算が速くなったことは分けて扱います。確定記録は `research/target-context-checkpoint.json` です。全キャラ・全効果の対応後には、主要計算・状態集計・転送・実行形状を含む全体の効率化を改めて計測します。
