# 共通武器メカニクスと実データ入力

`gpu/weapon_runtime.slang` と既存の戦闘・ダメージ実行器へ、自動連射のウォームアップ、可変拡散、分割装填を接続しました。実装、定義の梱包、fixtureはCUDA／Metalで共通です。CPUの発射履歴や途中状態をGPUへ渡しません。

## 連射・拡散

`mode: auto_warmup` は初期速度から上限速度へ、共有の発射カウンターで線形に補間します。発射間隔はカウンターを増やす前に捕捉し、同じ発射の拡散は増やした後の値を使います。間隔予約後の子通知で速度が変わっても、その発射が予約した間隔は変えません。

停止中の冷却は、前の発射が予約した間隔の1.5倍を超えたときに、実際の経過時間から減算します。装填開始時にカウンターを0へ戻す処理ではありません。連射速度と拡散は同じカウンターを使いますが、上限発射数は別に保持します。これは既存エンジンのモデルの移植で、線形な拡散曲線自体のゲーム内検証を追加で行った証拠ではありません。

`rate` は元データの連射速度をそのまま保持する入力です。従来の `interval` も使用できますが、両方を渡す場合は `interval == 1 / rate` が必要です。元の速度を逆数へ変換してから戻す際のbinary64の変化を避けるため、実データの正規化では `rate` を保持します。

拡散入力は `spread_start`、`spread_end`、`spread_shots`、`core_diameter` の4つを明示します。精度の補正後に直径を最低1pxへ制限し、コア直径との比率から共通の高精度powで確率を求めます。`accuracy_pct` は対象全員の拡散入力がある場合だけ受け付けます。固定のコア確率へ精度補正を黙って無視する受付はありません。

powの結果は、同じactorの正確なbinary64比率が同じ場合だけ再利用します。精度バフの失効や発射カウンターの変化で比率が変われば再評価します。固定比率の3発で評価回数1回、比率が変わるケースでは2回となり、確率とダメージはMPFRの独立期待値・CPU参照に一致しています。ゲーム状態の更新や命中通知は省略しません。

## 装填・チャージ周期

- 分割装填は `clip_count` と `reload_ratio_pct` の積で1回の充填率を求め、`floor(最大弾数 × 充填率 + 0.5)`、最低1発を加えます。ダメージの偶数丸めとは異なります。
- 31発・3分割なら10発ずつなので、最後の1発を入れる4回目が必要です。満タンに達するまで射撃を止め、中間の装填では `event:full_reload` を出しません。
- `reload_speed_pct` は1回の装填時間に反映します。次の部分装填が始まるときは、その時点の補正で時間を設定します。0秒でも、同じフレーム内で全装填を繰り返す処理にはしません。
- 通常武器の `post_reload_delay` は満タンの完了後から待ちます。完了通知で武器変更へ入った場合は、その場で射撃モデルを選び直します。
- チャージの `min_cycle` はチャージ開始時刻を基準に判定します。解放時刻から固定の長い待ちを足す方式へ置き換えません。
- `gauge` は命中単位の値、`gauge_mult` はその後に掛ける百分率で既定100です。静的な武器入力ではカメラ所有を明示して選び、実行時のカメラ切替ポリシーへ接続済みとは扱いません。キャラ別の `core_mult` も保持します。

## 実キャラからの静的正規化

`app/portable_weapon_input.py` は既存CharStateの初期化で解釈した武器メタデータを読み、同じ機械入力へ梱包します。CPUのtickや戦闘実行は呼びません。203体の監査では131体の武器入力が梱包でき、72体は未接続のチャージ後のカバー／自動装填ポリシーを理由に拒否しています。

これは武器入力のpreflightであり、全効果・装備・運用を含むGPU検証ではありません。通常画面の実編成経路、全キャラGPU対応件数は0体のままです。実定義のメタデータ・量補正・残りの効果、敵個体の状態、通常画面の入力アダプターを引き続き接続する必要があります。

## 検証

`tests/fixtures/portable-weapons.json` に24ケースを保持しています。手書きの状態・ダメージ期待値をMetalで確認し、GPU実行後に実際のCPU CharStateでも回帰比較します。コア確率の期待値はMPFR 256bitの上下方向の丸めが一致する値です。通常のGPU入力生成ではMPFRもCPU武器実行も使いません。

```sh
.venv/bin/python scripts/verify-portable-combat.py --backend metal
.venv/bin/python scripts/verify-portable-events.py --backend metal
.venv/bin/python scripts/verify-portable-api.py --backend metal
.venv/bin/python scripts/audit-portable-catalog.py
.venv/bin/python -m unittest discover -s tests -p 'test_portable*.py'
```

統合ケースは130正例・3拒否、単体検査は17件です。APIでは固定比率のpow再利用と31発の4回装填も確認します。現在のwire ABIは `0x50455637`、入力8,192語・出力16,384語、最大バッチ256です。各領域の重複と転送上限を単体検査しています。最新のCUDA確認状態は `research/portable-combat-checkpoint.json` を参照してください。前段106ケースのCUDA／Metal一致は `portable-combat-v6-checkpoint.json` に固定しています。
