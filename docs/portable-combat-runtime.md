## 接続と受付範囲

`POST /api/portable-events` の `combat` 入力から、既存の共通Slang実行器へ接続しています。`gpu/combat_runtime.slang` と `event_runtime.slang` を同じエントリーにコンパイルし、CUDA／Metalで数式・状態・期待値を共有します。転送アダプターは変更せず、binary64も既存の整数実装を使います。CPUで生成した発射時刻・バースト履歴・途中HPを入力へ渡す経路はありません。

今回受け付ける機構は次の範囲です。

- 固定間隔の自動射撃、自動フルチャージ。各発射は弾薬1・最大64ペレット×8銃口（512命中）。係数はペレット数で割り、命中ごとに偶数丸めと最低1を適用します。容量、弾数、次回可能時刻、チャージ期限、装填期限、発射数をGPUで更新します。
- 既存の `weapon_change` 定義から一度だけ変換したモードへの切替・置換・トグル終了、時間／発射数による終了と名前指定解除。終了通知からの再入も同じ実行器で扱います。
- 命中ごとの固定ゲージ獲得と100での消費、段階1→2→3、各発動者のクールダウン、段階間0.1秒、段階3後0.37秒、10秒のフルバーストと50%加算。ゲージ到達は次のフレームで判定します。段階1／2は最初の候補を待ち、段階3・再突入枠は最初に準備できた候補を選びます。段階Aと、効果による段階上書き・現在の段階への再突入にも対応します。
- 本体1・追加の敵最大7の独立HP／防御。型・ID・世代は既存の `impact_specs.ActorHandle` で検査します。指定照準が死亡中なら、生存する最初のスロットへ切り替えます。生存対象がなければ弾薬・ゲージを消費しません。
- `target` と `boss` の振り分け。周期ダメージは対象スロットと出現世代を捕捉し、死体・旧世代への時計を次の時計パスで無効にします。別世代へ再付与した場合は、古いDOT位相を引き継がず期限を再設定します。
- 開始、バースト使用／フルバースト開始・終了、装填完了、最後の弾、弾薬消費、フルチャージ、攻撃・命中の通知を既存の効果コンパイラーへ接続します。弾薬消費通知は発射者以外の所有効果にも届きます。

`weapon_burst_target_connected: true` を返します。これは通常画面の実編成・180秒自律戦闘を接続済みにするフラグではありません。`autonomous_battle_connected: false` は維持しています。全キャラの武器情報をこの限定入力へ自動変換する受付もまだ追加していません。

## 入力とフレーム規約

`combat` は `weapons`（5件）、`targets`（1〜8件）、任意の `initial_gauge`（0〜100）、`reentry_delay`（既定0.5秒）、`trace`（`full` または `summary`、既定`full`）だけを受け付けます。武器の入力はキャラ名分岐のない、明示した機構の値です。

| 武器のキー | 意味 |
| --- | --- |
| `enabled` | 射撃を実行するか。バースト候補の登録とは独立。 |
| `mode` | `auto`、`auto_warmup` または `charge`。 |
| `capacity` | 弾倉容量。整数1〜10,000。 |
| `coefficient` | 基本係数（%）。`full_charge_mult` は別途適用。既定100なら従来の適用済み係数も保持。 |
| `full_charge_mult` | フルチャージの基本倍率（%）、既定100。 |
| `optimal`、`element_match` | 適正距離・属性一致のboolean。 |
| `interval` | 自動射撃の間隔、またはチャージ開始から次の開始までの周期。 |
| `charge` | チャージ所要秒。`interval >= charge` が必要。 |
| `reload` | 装填所要秒。0秒でも開始した次のフレームまで完了しない。 |
| `gauge` | 1命中で獲得する最終ゲージ。チャージ倍率の自動乗算はしない。 |
| `pellets`、`muzzles` | ペレット数1〜64、銃口数1〜8。弾薬消費は1、命中数通知は銃口数、ゲージは物理命中数に比例。 |
| `stage`、`cooldown` | バースト段階（0は候補外、1〜3、4はA）とクールダウン秒。 |

敵は `kind`（本体0、追加の敵5）、`identity`、`generation`、`hp`、`defense`、`active` を受け付けます。スロット0は唯一の本体です。防御は敵ごとに明示するため、`combat` と非ゼロの `environment.defense` の併用は拒否します。コア比率とコア加算は従来の静的な共通入力を使用します。追加の敵ごとの射程・コア形状は未対応です。

外部コマンドは従来どおり `[時刻, op, event, owner, arg, query, extra, extra2]` です。

| op | 動作 |
| --- | --- |
| 24 | 時刻tまで、まだ実行していない1/60秒フレームをGPUで生成し進行する。`arg=0, extra=0`。 |
| 4 | 部隊の1フレーム。`arg=0, extra=0`。発射の指示や途中状態は受け取らない。 |
| 20 | `owner` の照準をスロット `arg` に指定。 |
| 21 | スロット `arg` をHP `extra` で再出現させる。世代はGPUで加算。 |
| 22 | スロット `arg` を退場させる。 |
| 2 | 状態観測。戦闘状態・時計を進めない。 |

明示フレーム（op 4）は0秒から厳密に増加します。GPU内進行（op 24）は内部の次フレーム番号を保持し、同じ終点へ再要求しても重複実行しません。op 4とop 24の混在は拒否します。全コマンドは時刻順で0〜180秒、最大64件です。フレーム時刻は観測する時計の刻みであり、CPUで計算した射撃予定表ではありません。初回フレームはGPUで5人へbattle_startを通知します。重複する外部battle_startは拒否します。

各フレームは効果の時計→バースト→部隊の登録順で武器を実行します。サンプリング時刻に間隔を飛び越えても、1フレームに同一武器を複数回射撃する追い付き処理はしません。通常の連射では次回期限を加算して現在時刻以上へ制限し、チャージでは完了後に残りの周期を待ちます。装填開始は弾が空で次の発射時刻に到達したフレームです。

1発の丸め済みダメージをHPへ適用し、0で死亡させます。集計ダメージはオーバーキルを含み、HPは0で止めます。命中を受けた対象を子通知へ渡し、親の探索再開時とdispatch終了時に文脈を復元します。通知の対象継承は既存の `world_condition_specs.target_inheritance_events()` を共用し、コンパクト形式の名前付きhit_count（49）も同じ規約へ対応付けます。弾薬消費・装填・バースト等の通知は本体文脈へ戻します。

## 進行と診断ログ

例えばコマンド `[[180,24,0,0,0,-1,0,0],[180,2,0,0,-1,0,0,0]]` で、GPU内で0〜180秒を進めてから1回観測できます。途中の観測が必要なら終点を順に増やします。GPU内進行に限り、最初の命令時刻を0にする必要はなく、初回にGPUが0秒の開始通知を送ります。`gpu_timeline_connected: true` はこの経路を表し、実編成経路の `autonomous_battle_connected: false` と区別します。

`trace: full` は全件を保存する要求で、効果発動128件・バースト64件を超えればstatus 8で拒否します。`trace: summary` は診断の各行を保存せず、`trace_total`／`burst_trace_total` に全発動件数を記録します。ゲームの状態更新や子通知を省略・切り詰める設定ではありません。60秒DOT240回と180秒の多数のバーストでも全ダメージを確認しています。容量を超えた全保存の要求は、黙って集計モードへ変更しません。

## 武器変更と通知中の状態更新

効果定義は既存の `detail_gpu.compile_effects` を共用します。`weapon_change` の係数、容量、連射速度、チャージ、ペレット／銃口、ゲージ、コア倍率、初弾係数等はその生成行から梱包します。独立したMac用キャラ定義はありません。静的な連射／自動チャージだけを受け付け、ウォームアップ、キャラ別の入口遅延、入口装填、動的な容量、skill_damage、100以外のフルチャージ倍率は拒否します。チャージ係数の演算順全体を未検証のまま変更しないための境界です。

モードは自分だけに適用し、時間の終了はフレームの効果時計、`duration_bullets` の終了は実際の発射数で判定します。有限の時間制モードは弾切れで停止し、無期限で有限弾倉のモードは装填します。無限弾倉（`max_ammo=-1`）は時間・トグル・解除で終了し、発射数寿命との併用は拒否します。無限弾倉の読み戻し弾数0は「消費する弾倉なし」を表します。

切替時は新しいセッションとして弾倉・チャージ・発射待ち・モード内発射数を初期化し、同じモードの通常再付与は期限を更新します。終了では先にモードを消して通常弾倉へ戻し、`event:state_end:名前` を同期通知します。子が再入・置換したセッションを親の後処理が上書きしないよう、世代を照合します。通常武器からの装填完了でモードが変わった場合も、その場で射撃モデルを選び直します。

1発の係数と各ペレットの丸め済みダメージは通知前に捕捉します。途中のペレット通知で攻撃力やモードが変わっても、その物理的な1発の後続ペレットは再計算せず、別の敵へ付け替えません。ペレット命中通知は各物理命中、攻撃通知は1発、hit_count／フルチャージ命中／最後の弾は銃口ごとです。通常射撃とチャージで異なる弾薬消費通知の順序も維持します。終了通知が通常弾倉を復元した場合、親の古い1発がその新しい弾倉を減らしません。

## バースト再突入

`instant / burst_reentry` の保留要求と、`buff / burst_stage_override:reenterN` の有効な状態の存在を既存の規約で扱います。要求値やNで別段階へ飛ばず、発動した現在の段階へ一度だけ追加枠を開きます。値0の状態も存在で判定し、既に期限切れなら適用しません。保留要求は発動者の次の使用で消費し、段階ごとの追加枠は1サイクル1回までです。

追加枠は指定の待ち時間後に候補とクールダウンを再確認します。再入中の段階入口通知は最初の試行と、準備期限へ達して再試行する時点で送ります。候補が準備できなければ期限まで待ち、再入が終われば元の次段階へ進みます。段階上書きは登録順で最後の有効状態を選び、段階のスナップショットは段階入口通知より前に取得します。
