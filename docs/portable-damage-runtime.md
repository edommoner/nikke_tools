# 共通ダメージ式とステータス集計

`gpu/damage_runtime.slang` に通常攻撃と対応済みスキルの単発計算を共通化しています。CUDA／Metalとも同じSlang、既存コンパイラーの効果ID・命令、整数で実装したbinary64を使います。型・演算順をfloat32へ置き換えません。

## 接続した計算

係数 → 攻防差 → 加算ボーナス → チャージ → ダメージ種別 → 受領側倍率 → 属性の順で、binary64の演算を逐次実行してからint64の最近接・偶数丸め、最低1を適用します。範囲外は既存どおり数値エラーで拒否します。

- 通常攻撃の係数補正、攻撃力%、施術者の基礎攻撃力から変換した定額加算、防御無視。
- 通常／スキル別のクリティカル確率・倍率。通常攻撃限定の補正をスキルへ混ぜず、各確率は0〜1、クリティカル加算は最低0。4つの合計は補償和で集計。
- フルバースト、通常攻撃だけの適正距離、通常のコア確率と確定コアスキル、コア補正。
- 通常フルチャージと武器変更の `full_charge_mult`。基本倍率に倍率補正を掛け、その後に加算補正を足す。
- 攻撃ダメージ、バースト、装甲破壊、DOT、貫通、順次、付着、爆発、分配の対応済み単体スキル。効果の種別フラグは既存コンパイラーの行から梱包。
- 属性一致時の基礎10%と属性補正。一致しないときは属性補正を適用しない。

例えば基本250%・倍率補正20%・加算補正100%なら `2.5 × (1 + 0.2) + 1 = 4` です。チャージ開始時ではなく命中時に補正を集め、full_charge通知で付いた補正はその命中へ反映します。1発の散弾パケットは従来どおり通知前に捕捉し、後続ペレットで再計算しません。

`combat.weapons` の `coefficient` は基本の係数、`full_charge_mult` は百分率で既定100、`optimal`／`element_match` はbooleanです。武器変更は既存のコンパイル済み倍率・適正距離を使います。従来の「倍率適用済み係数＋既定100」の入力も同じ結果を保ちますが、倍率を両方へ二重に設定しないでください。

## 順序を保つ集計の効率化

`collectStats` は1ヒットに必要なステータスを一度の走査で集めます。効果の初回有効化／失効後の再有効化で登録順の配列を更新し、観測時に毎回次の登録順を全検索する処理を省きました。単なる更新・スタック追加は登録順を変えません。浮動小数点の加算順を変えず、再付与による順序変更と大きな値の打ち消しも共通ケースで検査します。

`benchmark-portable-stats.py` は32効果・60命中・64入力を各3回測定します。比較用の `gpu/benchmark_stat_scan.slang` はコンパイル時の定義で旧来の順序検索を選ぶだけで、計算本体・入力・期待値は共用します。MetalのGPU時間中央値は検索版19.86ms、登録順版14.60msでした。全入力と全出力のハッシュは一致しています。約26%の短縮はこの固定集計負荷に限る測定で、本体全体・実編成の性能ではありません。

```sh
.venv/bin/python scripts/benchmark-portable-stats.py --label before
.venv/bin/python scripts/benchmark-portable-stats.py --label after
.venv/bin/python scripts/verify-portable-combat.py --backend metal
```

## 検証と残る範囲

`tests/fixtures/portable-damage.json` に37ケースを一度だけ保持しています。手書きの期待値をMetalと、GPU入力生成後に実行するCPUの単発式で照合します。登録順ケースは独立BuffManagerの状態とも比較します。従来分を含む共通バッチは106正例・3拒否です。wire ABIは `0x50455636`、入力8,192語・出力16,384語で、新しい攻撃文脈は入力5632語から、効果フラグは各定義の31語目を使います。CUDAの最新確認状態は `research/portable-combat-checkpoint.json` を参照してください。

敵個体ごとのデバフ実体、受領ダメージ補正、AoE／部位／迎撃の命中生成、遅延・複数ヒット・スナップショット、実行時の速度・照準・チャージ時間補正、HP基準やコピー・量補正は未接続です。部位／迎撃／範囲バーストの補正値が存在しても、該当する命中種別を生成しない単体攻撃へ加算しません。未対応の入力を省略して受け付ける経路はありません。

実カタログの203体を通常画面からGPUへ接続した検証済み件数は0体のままです。監査ではチャージ倍率の入力・単発式が用意できたことと、実キャラの武器タイミング・編成アダプターが接続できたことを区別します。全体の完了条件は `portable-roadmap.md` を維持します。
