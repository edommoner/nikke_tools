# 部位スキル用の共通ダメージ因子

`gpu/damage_runtime.slang`の既存ダメージ経路を、バフ・敵補正を取得する`sampleDamageFactors`と、取得済み値から順に計算する`damageFromFactors`へ分離しました。CUDAとMetalは同じSlangを使用します。7因子の除算・乗算順、最後の整数化、最小1の規約は保持しています。binary64本体、整数変換、pow、normalizer、canonical参照は変更していません。

追加の2スロットはコア適用前の第3因子と、部位補正を一度だけ加えた第5因子です。部位値では本体のコア・intercept補正を持ち越しません。`damageValueWithPart`は同じ取得済み因子から本体・部位の値を作るための入口です。本体との比による逆算、バフ再照会、fraction samplingの二重実行をしません。ただし、この二値入口はまだ戦闘receiptに接続しておらず、受付は従来どおり拒否します。

共通CLIの`damage-factors`は生産コードと同じ`damageFactorProduct`を使用し、独立したhost binary64の順次計算と全bit比較します。16入力はゼロの本体因子、subnormal、異なる部位因子、演算順序や比からの逆算で差が出る値を含み、Metalで一致・GPU再実行なしの独立sealを確認しました。これは積の検証であり、二値入口の状態取得回数や部位の実戦対応を認定するものではありません。

最初のプローブは先頭status出力を欠き、CLIの成功規約に違反しました。元capture `/tmp/nikke-parts-factors-probe-v1-metal`を保持し、statusを修正した別package/captureのv2で検証しています。集約packageの最初の準備も、準備中のソース変更を検知してGPU前に停止しました。失敗を上書きせず、固定した別packageを使用しました。

最終候補はMetal849ケース（native676・拒否173）と実編成4ケースが全件一致し、独立sealに成功しました。旧849の2,670,723,072byte、旧4の12,582,912byteはそれぞれ全byte一致、入力・native・出力の全entriesも同一です。Runtime stride138952は維持し、共通include追加でsource closureは110から111へ変わります。CPU事前検査307件、部位参照の影響13検査も成功しました。詳細は`research/portable-damage-factors-checkpoint.json`を参照してください。

歴史的なdefinition-view検査は元のconsumer SHAを保持し、今回の数値分離2ファイルを厳密な別SHAの変更台帳として扱います。元ソース不変や数値一致の証明と混同しません。未承認のfactor変更を拒否する負例を追加しています。

次は実際の生成時点で二値入口を呼ぶ診断を追加し、Frameのcoefficient寿命終了後のsnapshot、周期snapshotと重ならないreceipt bank、着弾時のlive部位選択、群ダメージ適用後のcallbackへ接続します。静的part・dynamic part・interrupt・座標・deferredの差は`portable-parts-skill-next.md`の契約を維持します。Windowsの追加実行は`portable-scope-windows-stop.md`の理由で停止中です。全キャラ・全特殊効果のGPU対応は未完了です。
