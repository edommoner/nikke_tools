# 共通着弾キューと吸血回復

ABI `0x50455657` の検証中です。同じSlang・静的効果定義・fixture・CPU参照をCUDA／Metalで使います。通常画面のCPU選択と、全変種認証0/203体は維持します。最新の両GPU認証コミットはcheckpointの来歴を確認してください。

## 着弾の位置

スキルの量は発動時に捕捉します。名前付き命中通知で攻撃力が変わっても、親の捕捉済み量は再計算しません。通知から生じた子は登録順にキューへ加えます。GPU生成フレームでは周期・段階DoT・失効処理の後、バースト処理の前にキューを排出します。通常弾は射撃・命中・最終弾・モード終了の通知を終えてから着弾・回復し、そこから生じたスキルは次の収集フェーズへ残します。

キューの末尾は排出中も読み直します。回復通知が追加したスキルも、CPUのリスト反復と同じ順序で処理します。B3保留は全量を先に算出してから着弾し、回復中に追加された次の保留を親の消去で失いません。実編成の静的入力アダプターは、このネイティブ経路と終了時の最終排出を使います。外部刺激だけの従来の部品検査は即時着弾を維持します。

吸血にはネイティブ着弾経路が必須です。HP率・境界通知の同期後に回復通知を届けます。回復元は攻撃した本人という既存モデルで、味方が付与した吸血の実機上の回復元は未確認のため、APIはモデル警告を維持します。正の率なら満タン・回復倍率0・HP加算が丸めで消える場合も通知し、非正の率は通知しません。分割の配分・丸め後の実パケット量で回復し、オーバーキルはそのパケット量を使います。

## 配置と境界

CPUから着弾予定表や途中状態は渡しません。入力末尾の余白8ワードは方針だけを持ちます。キュー本体はGPU専用の出力領域で、各プログラム2048レコード、各12ワードです。行・継承対象・保持対象・量・発動時刻・命中番号・深さ・出現epochを保持します。保持対象は新しい出現へ付け替えません。選び直す効果の対象は着弾時に決めます。部位・飛翔体・シールド等の世界モデル全体は残る接続の範囲です。

入力strideは77824ワードを維持し、出力は69632→98304ワードです。Runtimeの私有配列とFrameフィールドは増やさず、方針用uintを1個追加しました。2048件の境界を通し、2049件はstatus64、数値overflowは16で拒否します。仕事量にも4096件の上限があります。未使用のキューレコードを毎回GPUで全消去せず、カウントで有効範囲を管理します。記録の圧縮とキュー操作の効率化は、正しさの検証後の測定対象です。
