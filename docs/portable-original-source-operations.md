# 元編成の強制スキル使用と持続時間延長

`coordinate-original-source`は元Julia（율리아）の愛蔵品1/2/3の全77／79／79定義を各3秒、元サクラ：ブルームインサマーの全74定義を対照／実部位破壊の各18秒で検証する5ケースです。元のpublic body・全効果・weapon・成長・操作を保持し、計算済みの発火／射撃／対象スケジュールをGPU入力へ渡しません。

新入口 `gpu/world_coordinate_original_slot_entry.slang` は既存の共通kind33 `force_skill_use` とkind15 `named_buff_duration_extend` をsampled受付へ接続します。CPUとSlangのkind条件は同じ宣言から生成。CUDA／Metalの別実装は作らず、既存のsource-mask／同期待機frame／名前指定carrier／DoT期限処理を使います。数値規約・wire・Runtime容量は変更しません。

元Juliaは愛蔵品1でスキル1を1定義、2/3で3定義、元サクラはスキル2を2定義、時刻0に実強制発動します。sourceに属する条件付き定義は元の条件処理を通ります。時刻0のnative周期時計は空で、空の前後一致を非空時計の保持証明へ広げません。

サクラのparts worldは0.5秒にHP1の実部位を開き、実ダメージで1.0秒に破壊します。部位には公開のlive-parts入力と同じ `emit_on_destroy: [event:part_destroy]` を宣言します。最初のprobeはこの指定がなく、破壊しても延長未発火でした。単に時刻イベントを足さず、実破壊の翌frameから元の通知経路を使います。

通知後、自己buff「춤추는 꽃」と敵DoT「벚꽃잎」の期限が15.0→25.02に延長されます。実nativeの非空periodic grid、activation時刻、DoTの次tick2.0は変わらず、DoT expiryも25.02へ更新します。18秒の実戦闘まで追い、旧期限15秒以降に元DoTが実ダメージを出すことを正例に要求します。対照worldは部位破壊・延長・旧期限以降の同DoTダメージがありません。

受動observerは元row／owner／nameを検査し、実dispatch・実 `_activate` 呼出しと既存carrier／timerのfieldsだけを読みます。対象解決・stat再照会・発火スケジュールの変更はありません。比較は既存全battle／packet／RNG／resourceに、元操作発火数・選択された全最終carrierのmembership／stack／activation／正確な期限、全periodic clockとDoTの次tick／expiryを追加します。

旧cleanse入口は新macro未定義でCUDA／MSL原生成物が全byte一致。strict source／transport inverseと祖先projectionを維持し、normalizerと旧goldenは変更しません。共有fragmentのraw source hash変更を隠さず、旧生成物保持と新入口の証明を分けます。

開発v1のM5実行ではJulia3件が一致し、サクラ2件は厳密な集計検査で停止しました。保存出力の追加native照合により、連撃10発は実際には一致し、最初の差は時刻4.25の後続DoT rampでした。生成CUDA／MSLでresident RuntimeのstagedScope書込みがdispatch前に欠落し、ramp indexだけ10まで進んでも係数overrideが0のままでした。新入口では既存staged headerの未使用4wordへscopeを保存し、noinline scalar snapshot後に設定・dispatch・復元します。Runtimeやwireのサイズは増やしません。これは生成物の観測事実であり、コンパイラ内部原因の断定ではありません。

同じ失敗では敵DoTの持続時間延長も欠落しました。wide enemy carrierはscalar allied maskではなくperiodic target tupleにmembershipを持つため、延長の共通対象交差判定へそのtupleを接続します。比較器も同じ宣言BODY対象を正確に読み、scalar maskが空だからと敵DoTを除外しません。修正版v3はM5 Metalで全5入力一致し、別processのGPU禁止fresh監査68.982秒でも全件一致しました。失敗captureは`/tmp/nikke-original-source-metal-v1`に保持しています。


修正版のGPU計算は1.537584秒、初回pipeline生成92.290206秒、native事前検査63.582372秒です。失敗v1と修正版v3で全5入力／native指紋は不変で、先に一致していたJulia3件のreadback全21,238,272byteも不変です。GPU実行は計2回、同一claimの再試行0、hostの生成検査器／負例test修正後のGPU再実行0です。

`portable_scope_snapshot_audit.audit`は新しいbuffer scopeが生成物にある場合、CUDA／Metal両方で4scalarの事前snapshot、4word公開、dispatch、同じ値による4word復元を検査します。fresh生成と既存のcache読出し検査から同じ監査器を使います。実失敗／修正版の関数sliceと元全生成物SHAをfixtureに残し、欠落snapshot・公開・復元・noinlineの負例を検査します。生成物の構造検査を計算証明とは区別します。

kind分類は静的packing247/266を維持し、kind理由の拒否は22→16プロファイルです。kind受付の改善を6キャラの計算認定と数えません。次は依存分類で3プロファイルに影響するkind23 `force_reload`を優先します。盾回復27、遮蔽物復活30、damage蓄積34なども残ります。現CUDA実機、Windows warm cache性能、公開GPU受付・全キャラ認定は未達で、通常UIはCPUのままです。
