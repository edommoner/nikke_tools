# 周期処理の登録管理

周期即時効果と周期ダメージは、同じ「登録を捕捉し、期限を消費してから子通知を実行する」規約を使います。CPUは `timer_registry_runtime.execute`、GPUは `TimerSnapshot`・`timer_owned`・`advance_timer` を共通入口にします。発動者やキャラ名の分岐は追加しません。

## 時計を継続する更新と、作り直す更新

通常の継続ダメージを再付与する場合、次回の発動時刻は維持し、効果量や終了時刻を更新します。同じパス内で先行効果が後続の継続ダメージを再付与しても、後続は更新された効果量・終了時刻で予定どおり発動します。

周期的な自動攻撃、周期即時効果、段階的な付着の再設定は、新しい発動時刻を設定します。解除後の再生成も、同じ値が再登録されていても新しい時計です。実行開始時に捕捉した古い時計を使って、新しい登録を発動・前進させません。

自分自身の発動中に継続ダメージを再付与する場合に備え、現在の期限は子通知より前に消費します。子通知が読む次回時刻はすでに次の周期です。再付与で消費済みの期限を残して同じ時刻に二度発動したり、新しい期限を親の後処理がさらに進めたりしません。

CPUの `TimerRegistry` は通常の3要素タプルと同じ読み取り形式を保ち、時計の識別を付けます。継続ダメージの周期維持は明示した効果種別にだけ適用します。単に値が等しいという理由で解除・再生成を同一視しません。コールバックが失敗した場合、子が置き換えていない登録だけ期限の消費を戻し、イベント文脈は必ず閉じます。

## 実行順と期限

各パスは登録順の一覧を一度捕捉します。即時効果のパスとダメージのパスは従来のフレーム順を保ち、パス開始後に追加された時計はそのパスへ割り込みません。失効した時計を再登録する場合は登録順の末尾に移します。有効な時計の更新は位置を保ちます。

周期ダメージは既存の「即時初回は終了境界を除外、遅延初回は終了境界を含む」規約を維持します。終了境界のダメージでは補正の参照時刻を終了直前へ寄せます。周期即時効果は終了境界を除外し、有限／永続の条件評価と発動時の対象採取を別の方針として保ちます。これらは現在の参照モデルの規約であり、すべての効果の実機仕様を独立に検証した主張ではありません。

## 新しい効果の追加と検証

新規の周期効果では、時計を維持する再付与か、時刻を再設定する再付与かを定義します。同じ規約なら既存の実行器へ接続し、別のタイマー走査を作りません。新しい時刻・寿命規約が必要な場合だけ共通方針を追加します。

`scripts/timer_registry_cases.py` は、初回・終了境界、自分自身の再付与、後続の周期維持更新・解除・再設定・解除後再生成、定義順と異なる登録順における子の強化を手書きの期待値で確認します。CPUの発動トレースはGPU入力に使用しません。既存の周期即時効果6ケースと段階的な継続攻撃9ケースを再利用し、キャラ別の同じテストを増やしません。

採用版のnative/PTX各8ケース、軽い共通検査112件、既存の周期処理17ケース・発動順25ケース・混成10部隊が通過しています。継続ダメージの終了境界・周期維持再付与・自動攻撃の再設定・スタック参照・弾数寿命を含む既存ケースは、独立に実行したCPU/GPUの部隊全体のダメージと最終HPも照合します。標準条件で受付可能な187体の生成命令と武器入力は保存済みの版と同一です。ABIは `detail_timer_registry_v81`、確定記録は `research/timer-registry-checkpoint.json` です。

所持・装備・一時育成変更と運用切替を含む通常APIもGPU単独・CPU照合・CPU実行で一致しています。45秒の対象部隊は元の育成条件で653,679,911、一時変更後で692,308,676です。通常の召喚戦闘まで検証済みという意味ではありません。

この段階でも時計は効果定義単位です。敵の受領者ごとに異なる時計、予約着弾時の対象世代、通常の自動照準・召喚への攻撃経路は後続の接続が必要です。標準受付187/203体を全キャラの数値検証件数として扱いません。

## 効率化案の比較

機能確認版を `research/ports/v81-timer-registry-native-stage` に保存後、ダメージ側も即時効果と同じ連結索引へ接続し、並べ替えと順序番号の配列を削除する案を試しました。状態領域は1,260,136バイトから1,259,120バイトへ減りましたが、限定負荷の交互5組のGPU時間中央値は1,383.695msから1,399.098msで、短縮は確認できませんでした。

通常の装備・射撃・バーストを含む45秒・8部隊の交互3組でも、GPU中央値は6,697.434msから6,950.052ms、ホスト処理込みは6,887.783msから7,104.236msでした。入力と結果は同一です。メモリ削減が小さく、この測定で通常計算が遅くなったため、索引拡張案は採用せず機能確認版へ戻しています。API通信と結果キャッシュは含みません。実験の生成物と比較結果は `research/timer-registry-index-experiment.json` に保存しています。
