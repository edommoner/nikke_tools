# バーストのクールダウンと共有ゲージ

2026-10-19、ABI `0x50455642`。入力49,152語・出力40,960語、256定義・512実体・対象cache 1,024枠を維持しています。既存効果定義の `burst_cooldown`、`burst_cooldown_reduce`、`burst_charge_pct` を使い、計算は `gpu/burst_runtime.slang` と共通の状態・対象・時計・武器処理へ接続しています。CUDA／Metalに効果実装を分けません。

## クールダウン

持続バフ `burst_cooldown` は使用時の基本CDから引き、0秒を下限とします。新しい使用可能時刻を設定してからburst_castを通知するため、同じ通知による即時短縮が新しいCDへ反映されます。バフ値・使用可能時刻・加減算は共通binary64で処理し、演算結果が非有限ならstatus16です。

使用時に適用したバフ量を5人別に記録し、full_burst_start通知の後に現在量との差の正の部分だけを追加適用します。使用時に短縮した量を重ねて引きません。バフが失効・減少した場合にCDを戻すこともありません。この記録は開始時の照合後に0へ戻すため、前のサイクルで使用して待機中のB3も次のfull_burst_startで短縮されます。負の持続バフは使用時のCDを延ばし、負のinstant値は現在の使用可能時刻を延ばす既存CPUの規約です。

即時短縮は対象者ごとに `max(現在時刻, 使用可能時刻−値)`。全員・除外・状態・順位など既存の即時対象選択を再利用します。誰にも当たらない有限予算の効果は予算を消費しません。CDを待っている候補maskを保持し、短縮が届いた後は待機時刻を再計算します。段階間0.1秒・再突入・full burst入場0.37秒の待ちを短縮で消しません。既存の自動選択と同様に通常のB1/B2は先頭候補を予約し、再突入とB3では代替候補も選びます。明示的な使用順・pattern・delay等の実編成操作ポリシーは別途接続が必要です。

CD参照はCPUの辞書型buff queryに相当するため、CDバフがなくても未解決のmapped持続バフを解決する場合があります。使用前の参照、full_burst_start後の参照が対象順位を固定する順序も検証しています。CD定義がなく、未解決のmapped実体もなければ集計を省きます。

## 共有ゲージ

即時ゲージは正の値だけを共有ゲージへ1回加え、上限100で余剰を捨てます。対象がall_alliesでも5回加算せず、対象が空なら加算しません。通常の物理射撃からのゲージと同じ加算関数を使います。散弾10粒×銃口2からの20hit分とon_attackの即時加算を同じ射撃で確認しています。

既存CPUの `burst_gauge_charging` はcontroller tickの末尾で確定する値です。起動・外部通知・段階開始・full burst終了通知でもこの確定済み値を使います。したがって最初の段階開始通知は直前idleのgateを読み、終了通知は直前full burstのgateを読みます。この順序をphaseからの即時再計算へ置き換えず、CPU参照と一致させています。確定した充填窓の外での加算は破棄します。

## 検証と効率化

共通420正例・22拒否をMetalで検証し、追加31ケースをGPU読み戻し後に実際のCPU BurstController／BuffManager／CharStateへ照合しました。手計算値、使用可能時刻・適用済み量・待機mask・ゲージ・段階・使用者・回数、完全trace時の発動者と時刻を含みます。30秒のGPU内フレーム、複数サイクルの未使用B3、再突入、期限・stack、遅延対象、物理発射と即時加算の合流も対象です。CPUの途中状態や発動予定はGPUへ渡しません。CPU参照器は不変の武器・段階・CDだけを一時設定し、元データをfinallyで戻します。

HTTPには待機短縮、未使用B3への複数回適用、all_alliesの1回加算、物理射撃との合流を追加しています。29単体、旧イベント16＋拒否2、203体の武器のみ・203部隊の45装備定義初期化も回帰確認しました。
