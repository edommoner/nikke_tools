# 現在の開発ゴール

nikke_toolsの全キャラ・全特殊効果を、通常の画面・計算APIから共通CUDA／Metal実行器で計算できる製品機能として完成させる。最終目標とCUDA／Metal両方の完成条件は維持する。

## 現在の進め方

- Claudeが方針・優先順位・最小の実装単位・合格条件を決め、Codexが事実確認・実装・検証し、Claudeがチェックする。合格後、同じ分担で次の単位へ進む。
- Windowsはユーザーが明示的に利用再開を指示するまで使用しない。接続確認、status取得、依頼、催促、復旧質問、定期監視もしない。Windows待ちをMacでの開発停止理由にしない。
- Macで進められる未対応の効果・条件・組合せ、製品接続、数値規約、共通テストを優先する。既存のCPU由来監査を使って不足を整理し、ClaudeにMacで完結する次の単位を選んでもらう。
- CUDA／Metalの計算本体・効果定義・テストを共通化する。Metalでの合格をCUDA実行済みと数えず、未実施のCUDA確認を後続検証として明示する。
- Windows再開用に固定commit、要求body、期待input／全output SHA、成果物の出所、実行上限と再開手順を保持する。再開の明示後は保存結果・既存成果物を確認し、必要な最小差分のみ短く検証する。

## 再利用と正しさ

既存スキル・共通CLI・監査器・キャッシュを再利用し、小機能ごとにsuiteや監査基盤を増やすことを既定の解決策にしない。入力・計算コード・依存が一致する保存CPU／GPU証拠を再利用し、重複実行を減らす。失敗と独立監査は保持する。

許容差の拡大、効果の無視、期待値の書換え、比較除外の追加で差分を隠さない。CPU正本・pinned upstreamの変更は既存の明示許可範囲を守る。未確定の宣言モデルとゲーム仕様確認を区別する。CPU fallbackは安全な製品動作であり、GPU対応完了には数えない。

関連コード・テスト・検証結果のGitHub共有は既存のユーザー許可を継続する。個人設定・認証情報・生GPUバッファは含めない。Claudeへの送信は既存の具体的許可と実際の承認制約を守る。

## 進捗と完了条件

suite数ではなく、通常製品経路でGPU実行とCPU一致を確認したprofile／条件をMetalとCUDA別に報告する。静的取り込み、限定検証、製品対応を区別し、未対応条件と未実施CUDAを残件として保持する。CPU正本で意味を持つ効果・条件・相互作用の台帳と両backendの実証が揃うまで全目標完了とはしない。

現在の到達点：Metalの固定条件（180秒・期待値・seed0・core50・BODY1）で203キャラ／266 profile-stageをClaudeが合格判定。元条件258成功とsleep抑止の別条件8成功であり、全場面・全特殊効果・現在CUDA全件の完成ではない。Metal実証commitは4155099d、CUBIN監査修正も合格した固定consumerはc070896d2624fa1d9710b42e02bc79640537ef65。

Windowsの36秒CUDA1要求はローカルで準備済み・未依頼のまま保持する。今の次作業はWindowsの接続ではなく、既存coverage監査からClaudeとMac側の優先項目を決めること。
