# 元編成の強制リロード

`coordinate-original-reload`はミルク：ブルーミングバニー全81定義のauto／キャラ既定操作を各18秒、アスカ：WILLE全80定義を15秒、ジル全78定義を6秒保持する4ケースです。元の効果・武器・育成・設定を変えず、キャラ既定操作は公開bodyの`shooting_policy=character`だけで選びます。profileへcontrolを入れる案は正本schemaが拒否し、採用していません。元のtap／hold規約をそのまま使い、計算済みCPUスケジュールをGPU入力へ渡しません。

CPUの実観測ではミルクのcharge_holdで13.8秒、アスカの状態終了で13.2秒、ジルのburst_castで約3.633秒に自分の装填を開始します。auto対照は同じ18秒です。強制要求は装填中なら残弾や時計を変えず、そうでなければ残弾を空にして共通の装填開始へ接続します。固定時間、途中callback、分割弾倉、武器mode中の基準などは既存の共通handlerを使います。

既存`world_reload_native`の観測をcontextとして取り出し、元row／owner同定と要求前後の状態読み取りを追加しました。既存の通常suiteと元編成suiteは同じ観測器を使います。既存GPU出力readerも`portable_reload_observation.readback`へ切り出して共用し、予約word・kind・owner・phaseの検査を維持します。対象を再解決したり、statを追加照会するobserverではありません。重ねる既存profile observerがcanonical引数`self`を読むため、wrapperの引数名もそれに合わせています。

凍結パッケージから旧46ケースをfresh nativeで読み、固定Git blobの全native指紋を保持できました。旧source操作入口のCUDA／Metal原生成物も全byte保持しています。新macroを定義しない既存入口の数値や生成物を変えず、kind23をCPU／Slang共通の受付宣言へ追加します。

修正版v3はM5 Metalで全4ケース一致し、独立fresh監査89.704秒でも全件一致しました。静的packing247/266、kind理由の拒否13を全キャラ認定へ数えません。現CUDA、公開GPU受付・全キャラ認定は未達です。

開発v1のM5実行はautoミルク／アスカ／ジルが一致し、ミルクのキャラ既定操作で射撃履歴件数が不一致でした。保存readbackでは479射撃、nativeは471で、最初の差は12.533秒でした。13.8秒の強制要求自体より前の差です。nativeは判定用に予定したチャージの開始時、tapを選択済みでも`_force_full_charge=True`へ切り替えます。共通Slangは判定用のrelease時刻だけを設定し、tap latchの昇格が欠落していました。新入口では同じbranchでpartial-full latchを設定し、既存の保持判定・条件・強制reloadへ進めます。期間・効果・既定操作は保持し、修正版の別immutable packetで検証します。失敗captureとnative診断は保存し、同じclaimを再実行しません。


v2ではforce／装填開始・完了が全一致しましたが、装填後に3射撃の差が残りました。`partialCaptureCharge`が充填中にも最後のfull発射時刻を更新していたため、キャンセルされた充填が周期full選択を遅らせていました。新入口では発射可能時刻に達した場合だけ履歴を更新します。このidleの元編成では全full射撃がBODYへ届くため、実full-charge hit通知の最後の時刻とGPU履歴を追加照合します。旧v2の保存出力はこの検査で正しく拒否し、新たなGPU／native戦闘実行は0です。

実GPUは計3回（失敗2保持・修正版1成功）、同一claim retry0。修正版のGPU計算1.927328秒、初回pipeline生成92.538900秒、CPU事前比較82.375678秒です。全4入力／native指紋と、先に一致していた3ケースのreadback全21,238,272byteを保持しました。数値規約・wire・Runtime容量は不変です。

機能38／制御476検査が成功（Windows専用1skip）。旧46nativeの指紋は、既に各テストのsetupで行う観測を再利用する1検査へ組み込みました。二重のnative実行を増やしません。最終sealed packageはgeneration cache必須hit・Slang0で生成物一致を確認しました。これはCUDAコンパイルcacheや実GPUの成功ではありません。Windows新実行0、現CUDA未取得、通常UI CPU・全キャラ認定0を維持します。次のkind依存優先は3プロファイルに影響する27 `shield_heal_pct`です。
