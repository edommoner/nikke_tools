# 共通デバフ解除・免疫（検証中）

`debuff_cleanse`、`debuff_immune`、`debuff_immune:[名前]`、`debuff_immune_count` と、statを持たない名前付き状態を共通Slang実行器へ接続する。効果定義・入力・CPU照合はCUDA／Metalで共有し、通常画面はCPUを維持する。

解除は対象ごとに付与順でharmful状態を数える。harmful_irremovableは残す。0・負値・値省略は全解除、正の小数は整数化後も最低1件を解除し、巨大な有限値をint64へ狭めない。部分解除は残りの受領者と独立した発数マップを保持する。状態終了通知を出さず、周期タイマーも残す。

無制限・名前指定免疫は生存コレクションの存在を参照し、期限超過でもtickによる退場前なら有効。未解決のlazy状態や偽になった条件は、CPUが実際に参照する規則に従う。harmful付与時だけ判定し、harmful_irremovableやDoT登録へ勝手に広げない。

回数制免疫は同名の状態を所有者をまたいで共有し、残量を対象ごとに保持する。容量は同名状態の最大値で、加算しない。値なしと0値を区別し、最初の有値状態の順でプールを消費する。小数容量1.5は2回防ぐ。対象別発数のスタック上書きではなくCPUの代表スタックを使用する。通常再付与は名前・スタックの子通知をすべて終えた後、元の受領者の使用量を0へ戻す。stack initでは使用量を戻さない。

敵の無制限免疫は捕捉した世代を検査する。一方、現CPUの回数制免疫は世代を検査せず、正準名単位で残量を共有する。この相違は実CPUで観測した契約であり、ゲーム内挙動の認証ではない。

DoTは状態の対象と時計を分ける。部分解除後、状態が残っている間のダメージは残った対象へ向かう。全解除後も時計は残り、係数の参照先をCPUと同じ順序で再評価する。最大HPの解除後は外側の処理境界でHP比率を同期する。

## 配置と数値

ABI `0x50455663`、入力77824／出力102400 words。入力末尾の余白に8-word STATUSメタデータを置く。出力は32KiB増加する。5味方＋8敵×256名前のsoftware binary64使用量に26KiB、共有作業領域に4KiBを割り当てる。Runtime配列・スカラー、Frameフィールドの追加はない。生成コードのレジスタ・spill・ピークメモリを測定した主張ではない。
