# 共通GPUの遮蔽物HP

ABI `0x50455644`。CUDAとMetalは同じSlang・状態・効果定義・期待値・CPU参照を使います。遮蔽物の基本HP／現在HP／同期済み最大HP／効果から計算した最大HPと、受けたダメージを分離しました。入力49,152語・出力45,056語のままです。機構検証の増加に合わせ単一バッチ容量を1,024へ拡張しました。この容量は実編成での速度・メモリ上限の証明ではありません。

`cover_hp_pct` の基本値に対する加算率と、発動者の最終最大HPに対する加算値を区別します。計算順は `base * (1 + sum(percent)/100) + sum(caster_max_hp * value/100)` です。各実体の対象・stack・期限・発数寿命は既存の共通実行器で管理します。最大HPが増えた分だけ現在HPを増やし、減少時は上限へクリップします。壊れた遮蔽物はHP増加で復活しません。

`cover_heal_pct` は生存中の遮蔽物だけを回復し、上限へクリップします。既定は受領者の同期済み最大HP、`scaling: max_hp` は発動者の最終最大HPを基準にします。値0は通知せず、満タンへの有効な回復は `event:cover_healed` を送ります。1人の回復による子イベントを終えてから次の受領者を処理します。`cover_revive` は破壊済みだけが対象で、対象の同期済み最大HPに対する指定率で復活し、回復通知を送りません。0の復活や負の回復は理由付きで拒否します。

`allies_lowest_cover_hp:N` は生存者の残りHP比率順で、破壊済み・最大HP0・ダウンした者を除きます。同率は部隊順です。`self_cover_alive`／`not_self_cover_alive` は永久条件の参照時も再評価します。無作為な破壊済み対象、手動カバー操作、遮蔽物防御、バリア／分身、敵の攻撃経路選択は引き続き未対応で、受付を広げません。

外部刺激の命令26は、対象maskと計算済みの遮蔽物層ダメージだけを受け取ります。CPU戦闘履歴は使いません。この層が吸収したダメージは本体へ溢れず、HP更新・破壊判定の後で `event:cover_hit` を送ります。これはボスの防御計算・照準・層選択を完了した証拠ではありません。既存の命令25は体力層への攻撃で、将来の共通ボス実行器が各層へ接続します。

CPU本体は敵パターンがある場合だけフレームごとに遮蔽物最大HPを同期します。`cover_sync` はこの方針を明示し、単純な敵だけの実編成入力ではfalseです。その場合、育成効果から計算する最大HPは増えても、同期済み最大HPと現在HPは基本値のままです。未対応の敵パターンをCPUで動かしてGPU入力へ変換しません。

検証は `tests/fixtures/portable-cover.json` の独立期待値と、既存BuffManagerおよびtimelineの実instant handlerから得た32件のCPU参照を使います。実編成はミランダ・ドラー・ドレイク・N102・メアリーの3・30・180秒とSR15育成180秒を保持し、通常の71定義とSR15育成の91定義を全て含め、各人ダメージ・全バースト時刻・有効な武器待ち・HP・遮蔽物状態がCPU本体と4条件とも一致しました。最新の結果・両GPUの固定版・効率化は `research/portable-combat-checkpoint.json` を参照してください。

この固定編成の成功を全キャラ・全変種へ加算しません。全効果を含む全変種認証は0/203体、通常画面への接続も未完了です。[全体の完了条件](portable-roadmap.md)を維持し、残る周期対象・B3予約着弾・敵世界・保護層・操作・実編成を続けます。

遮蔽物HPに関係する定義がない場合は、新しい最大HP同期／参照の走査を静的な族maskで省きます。同じ共通カーネルの走査版と最適化版を、16入力×256定義×181フレームで3回ずつ比較し、入力・全出力を一致させたままGPU中央値が218.818msから140.951msへ約35.6%短縮しました。参照版は `PORTABLE_COVER_SCAN_REFERENCE` を使い、独立した効果実装を作りません。`portable-cover-benchmark-{before,after}.json` が証跡で、実編成の性能・メモリの証明ではありません。
