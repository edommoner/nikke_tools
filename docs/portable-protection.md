# 共通保護層

初期版 `dd1050c` で、保護膜・共有保護膜・デコイの生成／消費／回復、次の保護膜の増幅、作成者基準の保護膜無敵、遮蔽無効、`during_shield` と適用／消費通知を共通Slang実行器へ接続しました。CUDA／Metalの計算と入力・照合は共通です。通常画面はCPUを維持します。

## 契約

生成量は作成者の最終最大HPと代表スタックから求め、受領者ごとに残量と回復上限を保存します。全対象の量と「次の保護膜」消費を確定してから適用通知を届けます。再付与の計算が終わるまでは古い保護膜を参照でき、同名の別経路からの更新は最初の効果定義で量を再計算し、適用通知も送ります。通知中に元の状態が取り消された場合や別のインスタンスへ再作成された場合に、親の処理で新しい状態を上書きしません。

非貫通は最後に作成／更新された保護膜1枚へ当たり、破壊しても残りをHPへ通しません。貫通は捕捉した全保護膜へ同じ量を与え、遮蔽・HPにも同量を渡します。デコイは保護膜・遮蔽より内側で、遮蔽していない場合に1体が受け、貫通でもHPへ通しません。無敵は保護膜を作った側の状態を参照し、HP無敵とは区別します。これらは現CPUの明示されたモデルであり、暫定の重なり順などをゲーム実測で確定した主張ではありません。

保護膜の破壊通知は各膜を消費した直後に同期処理します。`end_on_shield_consumed` の終了は全膜の消費通知の後です。通知中に再付与されても、同じインスタンスなら予約した終了は残り、別インスタンスなら古い終了で消しません。デコイは破壊時に状態を終了します。部分的な名前解除ではCPUが残す対象別マップを保持し、全解除した状態のマップは利用しません。回復は期限内の既存状態だけへ、減った分まで、新しい適用時刻から順に行います。

CPU参照は、実際にインストールされた `timeline.simulate` から `_boss_attack` と `_land_squad` のコードを取り出して実行します。GPUの途中状態や被弾記録をCPUへ入力せず、CPUの結果もGPU入力へ渡しません。実行刺激の対象マスク・遮蔽マスクは手書きの機械条件です。ボスの自動照準・パターン予定・部位・均等分配など残る世界処理を実装済みとは扱いません。

CPUの最大HP直接集計が新しい `during_shield` 条件を無視する差分を確認したため、該当する実行時条件を検査し、外側の実行境界でHP比率を同期する参照補正も追加しました。保護膜のない初期状態では最大HP1000、最初の膜は100、その存在で最大HP2000となり、再付与の膜は200になることを独立した単体期待値で検査します。

## 配置

最適化版 `c411ddc` のABIは `0x50455665`、入力81920／出力135168 words。前版から入力16KiB、出力128KiB増加します。出力領域に512状態の対応表と最大1024オブジェクトを置き、512個の生存状態＋処理中の最大512参照を保持します。通知中に状態スロットを再利用しても、古い参照先の残量と作成者を取り違えません。オブジェクトは各対象の現在量・上限をsoftware binary64で保持します。

Runtimeの私有配列・スカラー、Frameフィールドの追加はありません。静的な宣言と割り当て量の比較であり、コンパイラーのレジスタ・spillや実際のピークメモリを測定した主張ではありません。共有輸送の出力word上限は262144へ更新しました。各バッチの32bit word添字と入力・出力長の検査は維持しています。

## 静的機能マスクの効率化

採用前のMac全24ゲートとWindows v57の実行・全転送終了を確認してから測定しました。無敵・遮蔽無効・次の保護膜増幅が定義にない場合だけ、その探索を省きます。ABI65の静的ヘッダはbit0が保護層あり、bit1が保護膜無敵、bit2が遮蔽無効、bit3が次の保護膜増幅です。GPUは効果定義から同じ値を再構成し、完全一致を要求します。ABI64の古い入力は拒否します。

候補の全1709入力で全出力ワードが採用前と一致しました。M5上で各候補を順番に実行し、warmupを除いた3標本の中央値は、32膜27.535→24.674ms（約10.4%短縮）、256膜332.400→283.381ms（約14.7%短縮）です。1膜13.081→13.150ms、無敵と増幅が存在する負荷28.209→28.365msは範囲が重なり、改善や退行を確定できません。元の機能探索は該当ビットがある場合に維持します。配置・Runtime／Frame宣言は変わりません。

これは明示した貫通被弾を繰り返す限定負荷です。実編成全体・CUDA速度・ピークメモリの測定ではなく、デスクトップのGPU活動も排除していません。最初のABI未更新の試験は採用せず別保存し、ABIを更新した候補を測定して採用しました。最適化の判断は `research/portable-protection-efficiency-decision.json`、全出力一致は `research/portable-protection-candidate-parity.json` を参照してください。

測定ツール `research/benchmark-protection.py` は採用前の `a198969` のapp/scriptsと検証終了のreceiptを使う履歴実験です。現在のABI65入力をABI64基準へ流すことを防ぐガードを追加しており、現在のチェックアウトでそのまま再測定はしません。
