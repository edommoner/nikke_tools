# 共通の自動追加個体照準

元のCPUの `BossScript._aim_enemy` は追加個体バケットを、現在生きている最古の追加個体へ解決します。再出現した個体は新しい登場順へ移り、追加個体がなくなると本体へ戻ります。これを共通Slangの一つの関数にし、武器フレーム・通常着弾コマンド・最近接の敵ダメージ／敵バフへ接続します。入力は照準方針と既存の個体記述だけで、CPUで選択した対象や射撃列を渡しません。

実験用combat入力の `automatic_add_aim` は部隊5人分のbool配列です。既定値はすべてfalseで、既存の明示スロット規約を保持します。命令27はownerの自動方針を0／1へ切り替えます。既存の命令20による明示指定は、そのownerの自動方針を解除します。命令26の遮蔽物ダメージは保持します。自動方針を解除した場合は保存済みの明示スロットへ戻ります。

同じフレームでも、前の射手や多段効果が倒した個体を次の選択から除外します。既存の共通登場順キャッシュを再利用し、HP・生存をキャッシュしません。最近接効果が取得済みの基礎列を照準関数へ渡し、同じ選択で基礎列を取り直しません。現在の自動武器実行は射手の武器イベントの前に対象を決めます。照準の座標・飛翔中の命中判定・部位・強制照準の世界スケジュールまで接続したという意味ではありません。

ABIは `0x5045564F`、追加入力はowner maskの1ワードです。既存の余白に収まるため入出力幅は各53,248ワードのままです。明示Runtimeフィールドの追加はuint1個で、GPU実配置のメモリ増分は未測定です。combat外の方針入力、5人を超えるmask、命令の不正owner／方針値はホストとGPUで拒否します。

23追加ケースは、再出現・退場・初期休止からの登場・明示指定への切替・owner4の最上位bit・多段ヒット中の死亡・同フレームの2射手・全個体不在を扱います。18件はCPU本体のダメージ／BossScript参照、3件は独立したBuffManager／ActorRegistry参照、2件は自動武器フレーム等の手書き期待値です。通常着弾のCPU参照は独立したダメージ式・ルーティング・精算の比較で、自動武器全体のCPU再生ではありません。

周期ダメージは未接続部分が残ります。元CPUでは単一定義の時計に加え、同名DoTの統合、対象集合保持、更新時の位相保持が関係します。対象別時計を追加すればそのまま互換になるとは扱いません。世界・保護層・効果資源・全変種認証と通常画面のGPU接続も未完了です。

Metalの読み戻しと全共通回帰、Windowsの短い固定版CUDA検証、局所測定は結果を確認して追記します。全変種認証0/203体、通常画面はCPUを継続します。
