# 基礎ATK／HPコピーの共通実行

`atk_copy`（canonical stat85）と`hp_copy`（stat86）を共通Slangのcarrier／状態／イベント実行器へ接続しました。CUDA／Metal別のコピー計算はありません。現在はprivate projectile worldの開発実装です。通常画面のGPU接続・全キャラ認定・新版CUDA数値一致とは区別します。

## 定義と状態

既存`base_copy_runtime.POLICIES`のselectorだけを受け付けます。コピー元は生存者の基礎ATK／HPが最大の者、同値は部隊順です。効果による最終値の順位へ置き換えません。静的入力にはselectorのpolicyを梱包し、CPUで選んだsourceやbasisをGPUへ渡しません。

MODE6〜9にmagic・canonical stat・軸・予約0を置き、quantity flag1024で既存unionと区別します。GPUはtag・kind・stat・対象・value・scaling・enemy／bullet flags・余剰語を検査します。stat85／86を64項目の数値ベクトルへindexせず、ATKコピーは既存atk_flatへ順序どおり加算し、HPコピーは実効最大HPとHP由来ATKへ接続します。

各carrierのbasis、前回HP gift、source、entry generationは既存出力内の専用6wordへ保存します。領域は`[763680,766752)`、lazy-bankの直後で診断tailの前です。既存private Runtime配列は増やしません。再利用時は新世代として初期化し、発動のprepareでsourceを選び直します。

## 発動と子イベント

prepareはnamed／stack子イベントより前です。子が準備済みATKコピーを参照してダメージを計算できます。HP付与は子の後で、同じdefinition／carrier／entry世代が生存しているときだけ行います。親が削除されて同じslotへstack初期化で再登録された場合、元の発動から新しいcarrierへ付与しません。

HP寄与は現在stackを使いますが、付与は今回amountと前回giftの正の差分だけです。単なるrefreshは再回復せず、回復倍率も掛けません。stack初期化ではbasisを準備し最大HPへ寄与しますが、発動HPは付与しません。

## 最大HP減少の同期

負値だけでなく、正のコピーでもsource戦闘不能後の再選択でbasisが下がります。参照アプリの静的reference-health同期が無効な場合、現在HPが最大HPを超え得ます。この既存方針をHP_UNCLAMP_POLICYで表し、CPUの中間HPや割合を入力しません。GPUのdescriptor受付も同じ機能へ接続し、HPコピーも負のdrainもない入力の偽装policyを拒否します。

失効時はnativeのstate_end子イベントが終わった後に対象別の上限処理が必要です。既存の有界removal queueに区別したcap通知を積み、Frame27で1対象ずつ処理します。HP crossingの子が終わってから次の対象へ進みます。参照・比較器・許容範囲を変更して差分を隠していません。

## 検証の経過

開発47入力はnative32正例＋不正wire15拒否です。値、逆転した最終順位、tie、自己／味方、refresh、失効、stack、子ダメージ、親／recipient削除、再登録、負のHP、正負重複の失効、終了子イベント、source戦闘不能後の再選択を含みます。GPUのbasis／source／gift／世代も実native carrierから観測した値へ照合します。

初回41入力の28正例は自己対象の受付コード誤りで拒否されました。修正後は負のHPコピー1件でHP1000／最大800＝125%と、GPUの800／800＝100%の差を検出。入力の同期policyを接続した次の43入力は、GPU側のpolicy受付未接続により関連3件が拒否されました。各失敗package／claim／raw／比較は保持し、同条件GPU再試行をしていません。

現在の47入力はMetal／nativeで全一致です。CPU全体695検査も失敗0（Windows専用1skip）です。旧428と新しい実編成6入力を含む集約481（native379＋拒否102）も全件一致し、新goldenを明示sealしました。旧428と新47の全input／raw／nativeも保存baselineと一致しています。実編成はギルティ／シン／クエンシーを各3秒／30秒、全定義のまま比較しています。

静的packingは196/266、基本キャラ137/203、分類108です。これは全キャラ戦闘認定ではなく、通常UIはCPUのままです。

sealの独立監査と直後のgolden生成が同じnative比較を二度行っていたため、監査内の新しい比較結果をそのまま使用するようにしました。元packageの監査・比較器・全raw検査は維持します。比較1回必須、比較0回／複数回／失敗の拒否、関数binding復元をCPU3件で検査し、CLI26件と実481のGPU禁止sealに成功しました。WindowsやGPUの再実行で効率を測ってはいません。

Windowsではこの機能を実行していません。v115のcompiler-only失敗を受け、追加の配列移動やnoinlineの連続試行、時間・メモリ上限の拡大を行いません。
