# 共通の弾薬即時操作と名前付きイベント

ABI `0x50455647`。`ammo_charge_pct` と `ammo_charge_flat` の受領者選択・現在の最大装弾・整数変換・増減・装填取消を、共通Slang `gpu/ammo_instant_runtime.slang` へ接続します。CUDA／Metalで同じ計算・入力・期待値を使用し、元CPUの登録済みinstant handlerとCharStateをGPU読戻し後に実行して比較します。

割合は `round(max_ammo * (value / 100))`、固定発数は `int(value)` です。演算順を保つソフトウェアbinary64を使い、前者は最近接・偶数丸め、後者は0方向切捨てを明示します。割合増減は残弾を0から最大装弾の間へ収めます。固定発数ではCPU同様に負の残弾が残るため、残弾状態と読戻しを符号付き32bitに変更し、加算は64bitへ拡張して上限判定を先に行います。負数は部分装填でも正しく回復させます。

大きな有限値が64bit整数変換範囲を超えても、正方向は上限へ、割合の負方向は0へ確実に収まるため、その結果を保持します。割合の浮動小数点乗算自体が非有限値になる場合、固定減算が状態の下限を超える場合は数値エラー16で拒否します。空の受領者集合では変換しません。固定発数の任意精度負数状態は未対応であり、丸めやunsigned wrapで成功扱いにしません。

通常武器はその時点のソース別装弾バフを使います。変更武器では装弾バフ適用の有無とセッションの最大装弾キャッシュを共有し、装填完了時だけ更新します。即時効果が変更直後の射撃より先に上限を参照する場合も、同じセッションの値を保持します。初期装弾はbattle_start通知後に設定します。

`reload_cancel_on_full` が真の受領者は、実行中の装填が満杯になった場合に装填を中止します。完了通知 `full_reload` や完了後待ちを新たに発行しません。このポリシーは実験用の静的武器入力に追加しており、通常画面の手動運用全体への接続を意味しません。

割合効果は全受領者への増減後に `event:<効果名>` を発行します。名前があり受領者が空の場合も発行し、固定発数版は発行しません。名前付き子イベントは既存の共通フレームスタックで同期実行し、発動回数上限や深さ制限を保ちます。予約済みの組込みイベントを任意名として読み替えず、未接続のshield等は拒否します。

効率化では入力記述子から、名前付きイベントを受信する発動者の5bit集合を作ります。該当発動者に受信定義がない場合に限り、イベントフレームを残して定義走査を省きます。HP更新・被弾に伴う子イベント処理、work／深さの計測は省略しません。`gpu/benchmark_named_event_scan.slang` は最適化前の全走査へ戻す比較用です。`scripts/benchmark-portable-ammo.py` が256割合補充定義×5受領者×20通知、16入力・3回の全出力一致とGPU時間を確認します。固定負荷であり、実編成全体の速度やピークメモリの証明ではありません。

48ケースの独立した手計算期待値には正負の丸め境界・巨大有限値・対象差・空集合・負残弾・部分装填・装填取消・変更武器・名前付き子効果・再帰上限を含みます。元CPUのhandlerによる参照も保持し、両者をGPU結果と照合します。通常入力・SR15の実編成は監査を通る全候補を対象にし、効果を省略しません。全変種認証と通常画面のMetal接続は引き続き未完了です。

開発中の失敗記録も保持します。`portable-ammo-source-change-readback.json` は実行中に検証参照を編集したため、ソース固定検査で停止した未検証の読戻しです。`portable-ammo-fixture-query-index-error.json` はfixtureで複数queryに同じ出力番号を割り当てた誤りです。連番へ修正し、CPU・GPUの全queryを照合する検証を再実行します。いずれも成功証跡として使用しません。
