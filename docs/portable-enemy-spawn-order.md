# 敵選択の共通登場順

全体対象・最大HP・現在HP・最小HP・防御順位・最近接の候補列を、GPUが作る共通の登場順へ接続します。旧版は再出現後も入力スロット順を使っていました。たとえば追加個体1の再出現後、旧GPUの全体対象は `[0,1,2,3]`、元のCPU本体は `[0,2,3,1]` でした。最大HPと最小HPの受領者差も実Metalで再現し、`portable-enemy-spawn-before-metal.json` に保存しています。

基礎列は本体を先頭に置き、追加個体を既存のenemyBirthと初期入力順で安定整列します。休止中のスロットも含め、選択時には現在の生存集合を検査します。再出現で登場順と攻撃力順位のキャッシュを無効化します。攻撃力順位も同じ基礎列から作り、同値時の登場順実装を重複させません。

HP順位はその都度software binary64で評価し、登場順だけをキャッシュします。以前のダメージで現在HPが減った場合と、再出現で最大HPが変わった場合も扱います。最大HPと現在HPを同じとみなした最初の手書き期待値は修正し、根拠を `portable-spawn-order-assumption-audit.json` に残しています。

最近接は共通APIで指定した生存中の明示照準を保ち、失効した照準は登場順で最初の生存追加個体へ移り、追加個体がなければ本体へ移ります。物理武器の照準関数は変更しません。`enemies_nearest_in_range` も既存CPUの論理的な照準規約へ接続します。空間座標や範囲形状の計算を追加したという意味ではありません。

ABIは `0x5045564E`、入出力幅は各53,248ワードのままです。新たな明示Runtimeフィールドはuint1個で、GPU実配置・総メモリの増減は未測定です。ホストから並べ替え済みの対象・生存状態・計算済みの時計を入力しません。CUDA／Metalの計算本体と期待値を分けません。

防御順位は現在のCPUモデルに追加個体の防御値がないため、非ゼロ追加防御の拒否を敵バフにも適用します。これまでのダメージ側と同じホスト／GPUの検査です。既存の非戦闘拒否テストは、新しい攻撃力メタデータを先にゼロへ戻し、元の戦闘所有条件を引き続き検査するようにします。

追加42ケースは34件の元のダメージ／BossScript参照、7件の元のBuffManager／ActorRegistry参照、1件の明示API照準の手書き期待値です。最後の1件は元のCPUの自動追加個体バケットが任意の明示スロットを表せないため、CPU一致件数に含めません。CPUの発動順や対象列をGPU入力へ使いません。

既存の `respawn-resets-generation-local-scored-health` はネイティブ参照のない手書きテストで、再出現後の順序を旧スロット順としていました。元のCPUと修正版GPUの登場順一致を確認して順序だけを修正し、ネイティブ参照を追加しました。6,000の総ダメージ・5,500の精算ダメージ・500の過剰分・対象ごとの精算期待値は変えていません。`portable-enemy-spawn-legacy-fixture-audit.json` に旧期待値と両者の読み戻しを保存しています。

敵の世界スケジュール、追加個体を超える動的部位・保護層・投射物、8体を超える容量、全キャラ・全効果・全変種の認証と通常画面GPU接続は未完了です。通常画面はCPUを継続します。

Metalでは814正例・96拒否、毎回登場順を作り直す制御版との全出力ワード一致、単体55件が成功しました。独立参照は敵ダメージ／選択の合計98件、敵バフ52件です。全26入力候補の通常／SR15・180秒の52実編成、203武器、203装備、固定8編成、HTTP追加4件も成功しました。新しいHTTPダメージケースではクエリーだけでなく対象順のパケット列も検査しています。52実編成の13読み戻しバッチは前段と全出力ハッシュが一致しています。
