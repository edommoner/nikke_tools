# キャラの育成変更画面の改善要望

状態：要望整理（未実装）。作成 2026-11-05。

## 要望

1. スキルレベルをスライドバーで変えられるようにする。
2. キューブは名前ではなく効果で表示する。
3. キューブのレベルもスライドバーにする。
4. オーバーロードは今の入力方式を残し、さらに部位ごとに効果とレベルを選べるようにする。表示は効果の数値で行う。

## 現状

| 項目 | 現状 | 出典 |
|---|---|---|
| スキル1・スキル2・バースト | 数値入力（1〜10）。取り込み時の値を横に表示 | `web/index.html` `#growth-dialog`、`web/app.js` `loadEditor` / `applyEditor` |
| キューブ | 名前のプルダウン（日本語名）と、レベルの数値入力（0〜15） | 同上、`data/cube-display.json` |
| オーバーロード | 9種類の能力ごとに、各行の値（%）をカンマ区切りで入力 | `web/roster-model.mjs` `overloadFields` / `parseOverload` |

計算に使われるのは `equip_skills` で、値は能力ごとの合計、または行ごとの%の一覧である。最大装弾数とチャージ速度は、同じレベルの行どうしで合計してから丸めるため、レベルが混ざる場合は一覧で持つ必要がある（上流 `runner/spec.py` §오버로드 장비 옵션）。

取り込み時に、上流の取り込み処理が部位ごとの内訳を `_overload` に書く。形は `{部位: [[能力, レベル], ...]}` で、部位は `머리`／`몸통`／`팔`／`다리` である。`_` で始まるキーは計算に使われない。

キューブの効果は上流の `spec.CUBES` にある。キューブごとに能力（`stat`）が1つあり、レベル1〜15の値と説明文（韓国語）を持つ。

オーバーロードの値の表は `spec._EQUIP_SKILL_TABLE` にある。9種類の能力それぞれについて、レベル1〜15の値（小数）を持つ。カタログでは `overload` として画面に渡している。

## 1. スキルレベル

- スキル1・スキル2・バーストを、1〜10のスライドバーにする。選んでいる値を数字で横に表示する。
- 取り込み時の値は今と同じく表示し、変更した場合はそれがわかる見た目にする。
- キーボード（矢印キー）でも操作でき、未取得のときは「未取得」と表示する。

## 2・3. キューブ

- 選択肢は効果だけで表示する（キューブ名は出さない）。例：「最大装弾数 ▲」。
- 選んだキューブの効果の数値を、現在のレベルで表示する。例：「最大装弾数 +29.69%（Lv15）」。
- 被ダメージ ▼ のように、下げる効果は向きを表示する。
- レベルは0〜15のスライドバーにする。装着なしを選んだときは無効にする。

## 4. オーバーロード

- 今の入力方式（能力ごとに、各行の値をカンマ区切りで入力）は残す。
- 部位ごと（頭・胴・腕・脚）に最大3行の入力欄を置き、各行で効果（9種類と「なし」）とレベル（1〜15）をプルダウンで選ぶ。選択肢の表示は値で行う（例：「攻撃力 +11.11%（Lv10）」）。
- 部位ごとの入力から `equip_skills` の行ごとの一覧を作り、計算に使う。部位ごとの内訳は `_overload` に保存し、次に開いたときに復元する。
- 取り込み時に `_overload` があれば、そこから部位ごとの欄を埋める。
- 2つの方式の関係：
  - 部位ごとに入力すると、カンマ区切りの欄も自動で更新される。
  - カンマ区切りの欄を直接変えると、部位ごとの内訳はわからなくなるため、「部位の内訳なし（直接入力）」と表示する。もう一度部位ごとに入力すると上書きされる。
- 能力ごとの合計を一覧で表示する（例：攻撃力 合計 +22.22%）。

## 決定事項（2026-11-05）

1. キューブの選択肢は効果だけで表示し、キューブ名は出さない。
2. オーバーロードのレベルはプルダウンで選ぶ。

## 進め方（Claude–Codexワークフローの単位）

1. スキルとキューブのスライドバー化、キューブの効果表示。
2. オーバーロードの部位ごとの入力と、既存方式との同期。
