# 物理攻撃の貫通・防御無視フラグ

固定検証ソース `7492d8b191471f820989dc760bc4adc91494cf6a`（GPU計算本体は `5a3ee26` とbyte同一）、ABI `0x5045566F`。`pierce_enabled` と `armor_break_enabled` を共通Slangの物理射撃へ接続しました。CUDA／Metalの効果ID・梱包・実行器・fixture・CPU参照は共通です。最新の検証状態は `research/portable-combat-checkpoint.json` を参照してください。

## 意味と攻撃の出所

両フラグは数値加算ではなく、有効な効果実体の存在で判定します。値なし・0・負値でも有効で、同名の重複やstack scalingで打ち消したり増幅したりしません。所有者とは別に受領者・期限・実行時条件を判定し、ちょうど失効時刻では無効です。不正な非有限の入力は拒否します。

既存のコンパイラーは、この2種の定義値を存在マーカーの1へ正規化します。fixtureの値なし・0・負値はこの共通の入力生成を経由する検証であり、生命令の有限値を網羅した検証ではありません。

既存の64要素のstat領域のID36・52を使います。`collectStats` の既存の登録順走査で存在を記録し、新しい状態配列・追加走査を設けません。物理射撃は武器変更中もフラグを受け取り、貫通／防御無視の対応ボーナスを既存のダメージ式へ渡します。1発の散弾のダメージは親パケットの捕捉値を共有するため、最初のペレットの通知で付いたフラグは次の発射から有効です。

`normal` というダメージ分類と物理射撃の出所を別に扱います。`auto_damage` などの通常型スキルや外部の通常ダメージ命令は、物理武器用のフラグを継承しません。スキルの貫通・防御無視は宣言されたdamage familyで決まります。これは固定版の実CPUのCharState射撃とスキル計算経路に合わせた区別です。

## 共通検証

`tests/fixtures/portable-attack-flags.json` の162例には、5所有者、自己／全味方、期限、有限／無期限の実行時条件、重複、参照scale、6武器、武器変更、複数銃口、散弾の親子通知、スキル／外部パケットの分類を含みます。入力は手書きの刺激と定義で、CPU戦闘の途中状態をGPUへ渡しません。GPU入力を作った後に実BuffManager・CharState・単発ダメージ式と比較します。スキルの参照は宣言経路の部品検査であり、全ネイティブ戦闘handlerの認証ではありません。

34件の不正な生命令も同じfixtureから両バックエンドへ渡します。効果種別、敵向けポリシー、非有限値、damage flags、未使用packet語を変更し、status64の拒否を確認します。入力とreadbackは比較前に保存します。

`research/portable-attack-flags-native-study.json` は導入前の102件のCPU調査です。`portable-attack-flags-native.json` は162件の共通fixtureのCPU参照で、両者を区別します。導入前調査だけでGPU対応済みとは判定しません。

## 新規実編成で判明したCPUの最大HP集計差分

最初の126条件では124条件がCPUと完全一致し、ベクハクの通常／育成後の2条件だけ、HPと最大HPの各5人分に差分がありました。固定版CPUの `effective_max_hp` は実行時条件を再検査せず、有効な実体リストのHP加算を残します。共通GPUは条件を検査し、無効化した加算と現在HPを戻しています。独立20ケースの手書き期待値をMetalで確認し、CPU側の異なる期待値も明記しています。

CPU戦闘やGPU計算は変更しません。実編成の照合では、この2つの固定180秒プロファイルに限り、実CPUの条件判定がfalseであること、対象HP効果が1件であること、CPUの加算値とGPUの基礎HPが計算通りであることを検査します。元の差分を保存し、ダメージ・バースト・武器状態などの他フィールドを免除しません。一般のHPフィールド除外ではありません。

最初の実編成検証器は一時的な生readbackを削除する設計だったため、この失敗時の全展開結果と証拠、再構成してSHAが一致する入力を保持しています。生readbackが保存済みとは主張しません。検証器を変更し、その後は全バッチの入力・readbackを展開・比較前に保存します。診断fixtureの最初の観測スロット重複も、入力・readbackとともに別記録で保持しています。

実編成の「一致」は既存のCPU観測項目（ダメージ・バースト・武器・体力等）の比較です。シールド残量など全内部状態の一致や、条件付きHP差分が被弾時へ及ぼす経路まで認証したものではありません。2条件の例外を全キャラ・全変種の認証へ加算しません。

固定版の上流シナリオ文書 `docs/scenarios/백학.md` にも、解除状態で最大HP加算が無効になる想定と、実体の名前が残る別の不一致が記載されています。今回の条件付きHP契約はこの意図とも整合します。シナリオ文書は仕様検討の根拠であり、実ゲームでの認証には置き換えません。
