# 物理攻撃の貫通・防御無視フラグ

固定ソース `5a3ee26039dc031f98ccd34a9c3245ff606a8808`、ABI `0x5045566F`。`pierce_enabled` と `armor_break_enabled` を共通Slangの物理射撃へ接続しました。CUDA／Metalの効果ID・梱包・実行器・fixture・CPU参照は共通です。最新の検証状態は `research/portable-combat-checkpoint.json` を参照してください。

## 意味と攻撃の出所

両フラグは数値加算ではなく、有効な効果実体の存在で判定します。値なし・0・負値でも有効で、同名の重複やstack scalingで打ち消したり増幅したりしません。所有者とは別に受領者・期限・実行時条件を判定し、ちょうど失効時刻では無効です。不正な非有限の入力は拒否します。

既存のコンパイラーは、この2種の定義値を存在マーカーの1へ正規化します。fixtureの値なし・0・負値はこの共通の入力生成を経由する検証であり、生命令の有限値を網羅した検証ではありません。

既存の64要素のstat領域のID36・52を使います。`collectStats` の既存の登録順走査で存在を記録し、新しい状態配列・追加走査を設けません。物理射撃は武器変更中もフラグを受け取り、貫通／防御無視の対応ボーナスを既存のダメージ式へ渡します。1発の散弾のダメージは親パケットの捕捉値を共有するため、最初のペレットの通知で付いたフラグは次の発射から有効です。

`normal` というダメージ分類と物理射撃の出所を別に扱います。`auto_damage` などの通常型スキルや外部の通常ダメージ命令は、物理武器用のフラグを継承しません。スキルの貫通・防御無視は宣言されたdamage familyで決まります。これは固定版の実CPUのCharState射撃とスキル計算経路に合わせた区別です。
