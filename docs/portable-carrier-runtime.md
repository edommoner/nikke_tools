# 定義と効果実体の分離

2026-10-19、ABI `0x5045563F`。入力49,152語・出力32,768語、定義256・実体枠512です。`gpu/carrier_runtime.slang` と共通Slangの状態・数量・HP・被弾・バースト処理が実体番号を参照し、定義は不変のまま、実体から定義への対応表を保持します。CUDA／Metalの計算・受付・fixtureは共通です。

## 保持する状態

発動予算・通知カウンター・周期時計・DOT／即時タイマーは定義ごとです。受領者、スタック、失効時刻、最終発動時刻、挿入順、最大HPのスナップショットは実体ごとに保持します。最初の定義数分の枠は各定義のprimaryとして予約し、それ以降を追加実体と再利用に使います。例えば256定義は256 primary＋256追加枠で、512個の同時実体を検証しています。枠が足りなければstatus64で拒否し、古い実体を上書きしたりCPUへfallbackしたりしません。

`carriers` 出力は定義別の `timers` 出力から独立しています。slot・definition・受領者mask・stack・active・end・activated・order・HP snapshotを出力し、失効済みの再利用可能な枠も含みます。`active` は保持状態のフラグです。戦闘入力では実フレーム／GPU時間進行が失効処理を進め、外部queryだけで時間を進めません。現在時刻がend以上なら数値集計からは除外されます。

## 対象と同名効果

静的対象に加え、持続バフのバースト使用済み／未使用・武器種との積・指定状態を持つ／持たないアクターを、発動時にGPUで選びます。対象集合が違えば同じ定義から複数実体を作り、以前の対象のスタックと期限を保持します。同じ対象集合への再発動は該当実体だけを更新し、挿入順を変えません。新規・再利用の実体は末尾へ入ります。対象は部隊順なのでこの受付範囲ではmaskが実体の対象同一性を表します。

同じ定義と対象を持つ実体を、同名の別定義より先に探します。条件を持たず統合可能な別定義は、発動者・名前・元stat識別子・最大stack・対象が等しければ、先に入った実体へ統合します。値と定義の属性は先行実体、期限は今回の定義から得た期限を使います。最大stackが異なる場合、元statが違う場合、実行時条件または条件付き有限passiveがある場合は独立です。同名の発動予算は統合しません。コンパクトstat IDが重なる場合も元statの識別子を別に持ちます。

装備の量補正成分は統合前にソース／グループへ丸める規約を維持し、既知CPU差異を引き続き別記して検証します。タイマー・DOT・武器モードの一般的な同名複数実体は今回の受付に含みません。順位・乱数・遅延解決の持続バフと、受領者別の発数寿命は次の接続範囲です。

## 終了通知

名前付き削除は全発動者の該当実体を先に片付け、その後で終了通知を挿入順に配信します。失効も対象実体を先に除去します。通知先の発動者・名前を有界queueに保存するため、子が実体枠を再利用しても通知内容は変わりません。queueは512通知、処理は明示的な32段の実行stackで順に進め、504終了通知をまとめてstackに積みません。queue／実行量の上限も失敗として返します。stack上限に達した状態の再発動は `stack_reach` を再送せず、失効時刻のみ更新します。

## 検証と効率化

共通325正例・12拒否条件をMetalで検証しています。追加18正例は対象変更・再訪・個別失効、同名統合と除外条件、独立予算、stack上限、全発動者の削除・通知中の再入、HP snapshot、504終了通知、512同時実体・失効後の再利用、追加実体からの量補正、ダウン後に対象集合が一致した場合の同一定義優先を含みます。追加15ケースはGPU出力を取得してから独立CPU状態と照合します。既存のHP116・武器77・単発式37・通知15・容量11のCPU回帰と、単体27、API、203武器・203装備初期化も維持しています。Windowsの短い実機照合の最終状態は `research/portable-combat-checkpoint.json` を参照してください。

単一実体かつ同名統合候補のない定義の初回発動と通常更新は、実体全体を走査せずprimary枠から処理します。追加実体ができた定義にはこの短絡を使いません。同名統合候補の有無は不変の生データから梱包し、GPUの状態をCPUで求めることはしません。

`benchmark_carrier_scan.slang` は短絡だけを無効にする測定用制御です。16プログラム・各256定義・初回＋32回更新、3回測定の中央値が870.332msから129.458ms（約85.1%短縮）となり、入力と全出力のSHA-256が一致しました。記録は `portable-carrier-benchmark-before.json`／`after.json`。実編成・通常画面・全体の速度やピークメモリを示す結果ではありません。

全効果込みの実編成GPU検証済みは引き続き0/203体です。一般の遅延対象・発数寿命・残りの特殊効果・保護層・敵世界・操作ポリシー・実編成／通常画面への接続と全体性能の検証を続けます。
