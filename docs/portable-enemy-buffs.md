# 敵対象の防御・被ダメージ補正

`def_pct`、`def_caster_based_pct`、`received_dmg_pct` の敵対象を共通Slang実行器へ接続しました。効果定義と対象選択、時間・スタック・同名統合は両GPUで共有し、CUDA／Metal専用の計算分岐を作りません。

アクティブ実体の受領者マスクではアクター種別を区別し、同じ名前の味方バフと敵バフを混同しません。敵の新規生存世代に単調な誕生番号を与え、実体ごとの捕捉番号と比較します。対象ごとの世代配列を全実体へ追加せず、1実体1ワードで、再出現後の参照と同名更新を保護します。複数対象の一部だけが新世代になった場合、交換されていない対象の旧効果は維持します。

敵補正の集計には活性化順の候補索引を使い、対象・生存世代・寿命・実行時条件を参照時に検査します。防御割合と固定値は防御因子へ、被ダメージ補正は対応する乗数へ渡します。固定防御の換算は発動者の基本防御を使い、全ての数値演算は既存の共通binary64です。

問い合わせは従来の対象0指定に加え、明示した対象の補正3値を返します。CPU参照はGPU実行後に元のBuffManager、ActorRegistry、BossScript、ダメージ計算を実行します。CPUの対象・時計・補正値をGPU入力へ渡しません。

既に接続済みの敵選択規約と生存対象上限を使います。攻撃低下、敵への発数寿命、残る敵状態・免疫・入射攻撃・世界全体の制御は未完了です。全キャラの全効果・全条件のGPU認証や、通常画面のMetal接続の完了とは扱いません。


共通ケースは725正例・85拒否です。敵補正のCPU参照36件は、8選択規約・重ね掛け・時間切れ・同名統合・味方との分離・世代混在・実行時条件・通知範囲を扱い、さらに3件のCPUダメージ因子を照合します。新しいケースにCPUとの差を許容する例外は設けません。

実入力の事前検査は17候補から21候補へ増え、追加4候補を含む通常／SR15の180秒・42実編成がMetalとCPU本体で一致しました。これは全変種の認証ではありません。固定8編成・203武器・203装備・HTTP経路も成功しています。

初回Metalパイプライン生成は約169秒でした。Macのコンパイル・ロック待ち上限を300秒、GPU実行待ち上限を120秒に分離し、起動は従来からの1グループ1スレッドをパイプライン記述でも宣言します。制御は通常終了、コンパイル時間切れ、GPU時間切れ、締切の切替、標準出力が先に閉じた場合を単体検査しています。数値34,874件と実証4件も新しい輸送処理で再実行しています。Windowsの短い検証の上限は変更しません。


固定版 `33e129b` はWindowsのRTX 3070 Tiでも低優先度・120秒上限の1回で48.796秒で成功しました。共通ソース・入力・全出力・検証コード・全ステータス・全ケース・既知差異を含む全CPU参照リストが一致し、生成CUDA/MSLも位置情報・改行・標準includeパスだけの正規化で一致しました。元のWindows作業状態と既存GPUサービスは維持し、検証用プロセスは終了しています。証跡は `windows-portable-combat-v27.json` と `portable-generated-v27-comparison.json` です。

索引の固定負荷測定は、255味方実体＋1敵補正、20秒・1,201射撃の16入力を各3回、他の検証終了後に順番に実行しました。入力・全出力のハッシュが一致し、GPU中央値は全実体走査の3.299106秒から敵候補索引の3.156267秒へ約4.3%短縮しました。これは敵補正の集計を含む固定負荷で、実編成全体の速度・メモリの認証ではありません。
