# 手動チャージ保持とカメラ所有権

`gpu/world_charge_control_entry.slang`はteam→fraction→spawn→enemy attack→periodicの共通実行器を継承するprivate入口です。通常画面はCPU、public/canonical world admissionはfalse、全キャラ戦闘認証は0です。CUDAとMetalは同じSlang本体、効果定義、binary64整数演算、入力、ネイティブ比較を使います。

ホストはCharStateの静的コンストラクタが正規化した操作定義と、効果の生のcharge_hold:N文字列を入力します。CPUが計算した射撃時刻、充填完了時刻、通知、カメラ所有者は入力しません。現時点で非アンカーのauto/hold/hold_until_close/hold_judgeと、時刻を明記したholdシーケンスを扱います。tap、アンカー、cover/reload/aim/burst操作、部隊のfocusシーケンス、復活は未接続で拒否します。

GPUは60Hzの共通時計で充填完了を実際に観測した時刻をラッチします。充填後に速度buffが失効しても完了時刻を再計算しません。閾値は秒数、生文字列の順に通知し、0.1と0.10は別の名前を保持します。各閾値は条件評価より前に消費し、条件が偽でも同じチャージ中には再通知しません。count:Mは既存の共通カウンタを使います。コールバック後の戦闘不能、武器session、reload、充填状態を検査して旧射撃の継続を決めます。

操作所有権は優先度、新規要求、部隊順で選び、先取りで保持を解放します。soloは所有者をカメラ対象とし、warnは静的カメラ、strictは実際に重なった要求を拒否します。burst段階の使用者、充填中/chain/本人full burstの窓は共通状態から決定します。hold_judgeの開始時刻はその時の有効charge時間と最後の閾値から算出します。同一burstアンカーの先取り後の再入は1回に限ります。開放時刻が未確定の保持はGPU内で正の無限大、JSONではrelease_time:nullとrelease_until_close:trueで表します。

入力は104136word、ABI0x5045568a/mode21です。旧98000wordの後に6136wordのWCH1/version1ポリシーを追加します。header16、owner5×8、click5×8×16、hold sequence5×8×8、threshold1280×4です。未使用領域、予約語、有限値、owner範囲、並び、eventの名前と秒数の対応をGPUで検査します。DOWN_Chargeのhold/hold_judge/明示hold禁止も静的コンストラクタとGPU両方で検査します。

出力は655360wordを保持します。653160からowner5×32、653320からheader16、653336から1280bitの閾値消費、653376からowner5×16個のアンカーbinary64、653536から220×8のtraceで、終端655296です。trace/アンカー容量超過はエラーとして扱い、長時間や全組合せの認証とは区別します。
