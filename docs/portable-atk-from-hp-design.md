# 最大HPから攻撃力へ変換する効果の共通接続

固定ソース `39bce8a`、ABI `0x50455672` でMetal／CUDAの全4070入力、Mac全47検査・単体263件・実編成136条件が成功しました。HP由来185正例・23拒否と、Macの追加実射撃80例を含みます。武器変更待機と保留B3倍率の未接続を解消し、旧134成功編成を保持、ラプラス2条件も検証しました。全検証・転送後の7負荷測定でHP基準値再利用候補は採用基準を満たさず不採用、全キャラ認証0/203・通常画面CPUです。証拠は `research/portable-mode-entry-broad-validation.json` と `research/portable-mode-entry-transfer-completed.json` です。

## 数値設計と初回試験の経緯

`research/characterize-atk-from-hp.py` は元BuffManagerで60条件を検証しました。全5所有者、自己／全味方、負・ゼロ・正の割合、無限／有限期間について、5受領者×4時点を観測しています。受領者の最大HP変化は即時に反映され、現在HPだけを1にしても攻撃増加量は変わりません。有限期間の効果も付与時のHPを固定しません。この調査はダメージ・実戦・GPUの認証を含みません。

元CPUの式は `recipient_final_max_hp * (value / 100)` です。除算を先に行うbinary64順序を共通数値演算で保持します。通常の `atk_flat` 集計後、HP由来の各項を順番に加え、その後にキャスター基準の各攻撃項を加えます。後者を既存の通常走査で先に足している実装へ単純な分岐追加をすると、混在入力の丸め順序が変わり得ます。旧入力の全出力保持と、桁差・打ち消しを含む混合ケースが必要です。

旧コンパイラーはこの効果をkind4・HP用フラグ241で表現しますが、共通実行器のkind4はバースト段階上書きです。BUFFSへの名前追加だけでは受付しません。専用の共通識別子と明示的な翻訳・生入力検査が必要です。既存64要素の数値配列へ無条件に添字を追加せず、元効果との衝突を検査します。

無限効果の未解決対象は、この後処理では元CPUが `_resolve_target` を新たに呼びます。通常の遅延対象キャッシュをそのまま使うと順位対象の意味が変わります。さらに `effective_max_hp` の条件再検査には既知のCPU差分があり、実行時条件付きHPのGPU契約を変えるかどうかは、独立した入力と元CPU観測で判断します。既存のベクハク2固定条件の差分例外を他の効果へ広げません。

当初の未検証事項は、通常flat／HP変換／キャスター基準flatの混合順序、重複・スタック・期限、実行時条件、順位対象、最大HPの各供給源、ダメージ実行と対象選択への伝播の元CPU観測です。その後に共通Slangへの接続、共通fixtureと拒否ケース、Metalの比較前readback保存、既存全入力の比較、必要な短いCUDA実行を行います。全キャラ認証は0/203のままです。

追加の `characterize-atk-from-hp-order.py` は60条件（全5所有者×全6登録順×自己／全味方）で、HP由来の +1e16／-1e16 を相殺した後にキャスター由来1を加えると、どの登録順でもflatが1になることを確認しました。効果全体の登録順で混在加算すると一部の順序で0になり得ます。元の順位用 `_effective_atk` はHP由来を集計せず、この入力では1001でした。順位へHP由来量を追加する実装は元CPUの契約を変えるため行いません。

この追加研究の最初の入力では通常 `atk_flat` 効果が元CPUの `_STAT_TO_BUFF` に存在せず、想定した通常flatは加算されませんでした。GPU差分ではなく研究入力の仮定誤りです。実際に対応するHP二項とキャスター項へ入力を修正し、元の関数や期待値の許容誤差は変更していません。


試験接続はHP由来とキャスター由来をそれぞれ元の保存順で後処理します。この効果が存在するときだけ通常のキャスター由来集計を後段へ回し、既存入力の丸め順序を維持します。順位が未解決なら毎回選び直し、通常の遅延キャッシュや対象履歴を更新しません。順位用の攻撃評価にはHP由来量を加えていません。Runtime・Frameのフィールドは増やしていません。

攻撃量の参照には、元CPUがHPの実行時条件を再検査しない規則を専用の最大HP集計へ写しています。HP表示・同期の既存契約は変えていません。期限はGPU保存枠のaliveだけに依存せず照会時刻で判定します。初回110例の期限漏れ40件、次の160例の順位先行固定8件をreadback付きで記録し、原因ごとに修正しました。現在185例・23拒否はその修正後で、初回の成功分だけを流用した認証ではありません。

185例には全5所有者、自己／味方、負・ゼロ・正の量、無限／有限期間、HP供給源、条件失効、順位移動、HP二項とキャスター項の丸め順序、スタック上限・期限・除去、無限の参照追従と有限の捕捉を含みます。23拒否は旧kind4との混同、敵／健康／通常集計フラグ、余剰パケット、非有限値、旧ABI、正負の算術オーバーフローです。元CPUのBuffManagerとcalc_damageをGPU読出し後に比較します。この成分検査は自律物理射撃や全キャラ実戦の認証ではありません。

固定ソース `0ae6a14` の全3539入力と追加実射撃80例はMetalで成功し、既存3331入力の全出力・展開結果・CPU回帰を保持しました。しかし全44検査は実編成段階で停止しました。134条件（132完全一致・既知HP差分2）が検証でき、従来130条件はCPU測定時間以外を保持しています。ラプラス：アルティメットヒーローの2条件は、無期限・条件付きの武器変更をアダプターが拒否するためGPU実行前に失敗しました。除外して全体成功とは扱いません。元の武器変更規則と既存GPUのライフサイクルを調べ、未接続経路を確認してから再検証します。診断は `portable-hp-attack-roster-admission-finding.json`、初回全体結果は `portable-hp-attack-first-global-gates.json` に保持しています。
