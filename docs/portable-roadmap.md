# 共通GPU実行器の完了条件と作業順

最終目的は全キャラ・全特殊効果を共通実行器で計算し、MetalとCUDAの実装・効果定義・テストを共用することです。小さな機構検証やコンパイル受付数を、この完了条件へ置き換えません。Windowsは必要な短い比較だけに使用します。

## 完了を証明するために必要な経路

1. 所持・育成・装備・一時変更・運用指定から、CPUシミュレーションを実行せずに共通入力を生成する。既存の定義・条件・対象・ライフサイクルの分類を再利用する。
2. GPU内で180秒のフレーム、武器・弾薬・装填・照準、バースト・クールダウンを更新する。発射時刻、子イベント、途中状態をCPUで計算して渡さない。
3. 共通数値の全演算と実際のダメージ式の順序を維持する。doubleをfloatへ一括置換せず、変換・powの境界を独立期待値で確認する。
4. 全ての登録された効果族、条件、対象指定、複数通知、効果実体と世代、予約着弾、味方HP・回復・保護、部位・飛翔体・追加の敵を接続する。未対応や意味の曖昧な入力を黙って省略しない。
5. 通常画面・単体／一括計算へ接続し、CPUフォールバックとの区別、未対応時の拒否、保存・復元を実際のAPIで確認する。
6. カタログ全203体を対象に、通常育成と宝もの等の変種の入力監査、各機構の独立期待値、実編成の基礎値・各人ダメージ・バースト・最終状態を検証する。CPU比較は回帰検査であり、仕様そのものの証拠とは区別する。
7. 新しく共通化した処理について、上記の正しさを保ったまま、代表的な単体／一括計算の時間・ピークメモリと処理内訳を計測し、必要な効率化を実施する。小さな検証カーネルの時間を本体性能の証明に使わない。
