# 共通の属性優位上書き

`element_code_override` はキャラの属性コードを変更せず、有効な上書き効果が持つ `target_code` と敵コードが一致したとき、ダメージ第7因子の属性優位を成立させます。キャラ本来の属性優位とORで合成します。`allies_code:` 等のロスター属性による対象選択は変わりません。対象コード条件 `target_code:` とは別の処理です。

## 入力と共通実行

ABI `0x5045566B`、専用の非数値stat ID88です。既存のlegacy ID85〜87（基礎値コピー・対象カウンター）と衝突させず、64要素の数値stat配列へ加算しません。入力86016／出力159744 wordsとRuntime・Definition・Frameのフィールドは維持します。

コード文字列は既存の名前プールへ完全一致で登録し、名前ID＋1を渡します。0は `target_code` 未指定／null、1〜256は文字列IDです。空文字・未知名・空白・コロンもそのまま扱います。敵コード未指定／null／空文字は上書きに一致しません。GPUにはCPUで計算した一致真偽を渡しません。

上書き定義のIDは、この非ダメージ定義では未使用だったdamage packetのrouteワードへ格納し、残る7ワードをゼロにします。入力のWORLD_METAはコードID・名前数に続く第3ワードを上書き定義数に使い、残る4ワードを予約ゼロとします。共通GPU admissionが実際の定義数・stat種別・ID範囲・ゼロの数値payload・予約ワードを検査します。値の大小や符号で判定せず、通常のスカラー量はゼロへ正規化します。

legacyコンパイラーには上書き定義を名前・対象・時計を持つbare buffとして渡し、共通入力側で専用statとコードIDを設定します。元の効果辞書は変更しません。legacyのCUDA計算本体や元CPUソースを変更せず、実行本体は同一SlangからCUDA／Metalを生成します。

## 元CPUの存在判定と期限順序

元CPUの `CharState.element_match` と `BuffManager.element_override_match` は、数値バフのクエリとは別の存在判定です。有効キャリアの対象所属を読み、数値の合計・スタック量・通常の実行時条件フィルターを使いません。未解決の順位対象を強制解決しません。永続passiveが条件不成立でも登録されている場合、その存在判定を保持します。

期限はキャリアのライフサイクルが管理します。通常フレームでは期限整理後に解除されますが、周期ダメージのcallbackは期限整理より先に動きます。例えば0.5秒期限の上書きが0.6秒の周期callbackでまだ存在し、その直後の期限整理で消え、0.85秒のcallbackには寄与しません。GPU helperもalive／対象所属を参照し、独自にend時刻で除外しません。この差は `research/portable-element-periodic-expiry-finding.json` に、最初の期待値と実CPU観測を保存しています。

同名・同statの別定義から更新した場合、元CPUは元キャリアの効果コードを保持して期限を更新します。別名なら独立して存在し、どちらかのコードが一致すれば優位になります。共通実行器の既存キャリア識別を使って保持します。
