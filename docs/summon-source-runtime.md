# 追加の敵の出現とHP

v71は、共通の敵識別表を使い、追加の敵の出現・通常HP・ヒット数制HP・途中切替・撃破・退場・再出現をGPUで管理します。キャラ名で分岐しません。既存の敵パターン実行器が出現と終了を決め、同じ設定IDを再利用した場合は既存のパターン出現世代を使います。CPUが決めた出現時刻やHPの履歴はGPUへ渡しません。

通常HPは実際に残っているHPまでを受領量とします。ヒット数制では1回の命中につきヒット数を1増やし、受領量は要求量と1の小さい方です。通常HPとヒット数制を併用する場合は、出現時刻に切替までの秒数を加えた時刻からヒット数制になります。HP制の受領量とヒット数制の命中回数は同じ数量として混ぜません。

要求したダメージと、HPプールに入った受領量を分離します。共通の型付き命中通知には受領量を渡します。撃破済みの対象へのダメージは過剰分として記録し、命中通知を追加しません。実際のボスへの合計ダメージも増やしません。吸血等がどちらの数量を参照するかは、その消費側の規則です。この実装だけで吸血や命中先ごとのダメージ計算を完成扱いにしません。

撃破による死亡通知は次のフレームの先頭で届きます。時間切れ・後続パターンによる終了・戦闘終了で退場する場合は、死亡通知を出しません。全滅・時間切れ・別パターン終了が同時に成立する場合、全滅による終了を保ちます。再出現時はHP受領量とヒット数をリセットし、全期間の受領量と過剰分は保持します。古い出現世代や不明な対象に向けた診断命中は拒否します。

HP上限・切替時刻・数・攻撃力等はパターン定義を参照し、対象ごとに複製しません。可変状態は受領量・ヒット数・退場理由を設定対象の枠で保持し、出現順はパターンごとの先頭順と枠内の位置から求めます。128枠は本体・部位等も含む共通の設定上限です。部位等がなければ追加の敵は127体までです。1部隊の可変状態は1,219,080バイトで、v70からの増加は2,240バイトです。命令幅344語・キャラ入力幅169語・敵入力の全長は増やしていません。

機能確認版では設定表を探索して対象を見つけます。その版を保存してから、検証済みの連続IDと設定表の先頭位置を使う直接参照へ変更します。先頭位置は既存ヘッダーの予約語266へ格納し、設定表との一致を検査します。可変状態へ別の索引を複製しません。

127体への32,512回のHP受領処理を5回測定した中央値は、538.096msから260.601msへ短縮しました。同じ入力と観測量で約2.06倍です。これは外部刺激による実際のHP更新・型付き命中通知の測定で、通常射撃の対象振り分けや部隊計算全体の速度向上を意味しません。既存の4部位・モード射撃を含む8候補の通常APIは、キャッシュなしの単回比較で6,916.5774msから6,913.4521msとほぼ同じでした。

診断入力14は実際の追加の敵のHPプールへ命中を適用し、入力15は敵パターンのフレームを進めます。問い合わせ134は、その時点の世代・生存・受領量・ヒット数・出現順・全体の累積量を返します。これらはCPUの戦闘結果をGPUへ再生する入力ではなく、共通の世界実行器を検証する外部刺激です。

検証では通常HP、ヒット数制、途中切替、全滅と後続パターンの競合、死亡を伴わない退場、上限枠を同じ表で扱います。既存CPUのHP処理と全観測点を比較し、主要な受領量・過剰分・出現数・死亡数には独立した期待値も指定します。古い世代・不明な対象の拒否後もGPUの同じコンテキストを再利用できることを確認します。キャラ別に同じ検査を作りません。

最終の上限ケースは32部位と95体の追加の敵を同時に置き、追加の敵のIDと物理枠の位置が異なる状態で末尾の枠へ命中させます。部位を追加の敵の生存数へ混ぜず、HPの受領先も取り違えないことを確認します。設定上限を超える場合は、対象一覧を生成する前に拒否します。7ケースがnative/PTXで通過し、共通の軽い検査87件、既存の命中5ケース・敵行動／被弾7件・混成10部隊・所持装備と一時育成変更を含む通常APIも通過しています。記録は `research/summon-sources-checkpoint.json` です。

この文書はv71の機能確認記録です。追加の敵が持つ攻撃は、その後のv72で[既存の被弾実行器へ接続](summon-attack-runtime.md)しました。v73では[敵数の条件](world-count-conditions.md)をフレーム先頭の世界状態へ、v74では本体／追加の敵の条件を[通知の対象文脈](target-context-runtime.md)へ接続しています。通常射撃やスキルの対象振り分け、命中先ごとのバフ・追加効果、実射撃からの同時命中通知は未接続です。自律照準と予約命中が持つ実際の対象も、この共通文脈へ渡す必要があります。通常の部隊計算では召喚を引き続き拒否します。標準条件の187/203体という受付数は増やしません。これらを接続し、実スキルが非ゼロ回数で発動したことを確かめる必要があります。
