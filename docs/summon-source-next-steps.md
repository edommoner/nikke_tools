# 残る通常戦闘への接続

v71で出現元のHPと世代は動きます。通常の召喚受付を開く前に、次の接続が必要です。キャラの受付数を増やすために、未発動の条件を無視したり、追加の敵を本体へ読み替えたりしません。

## 追加の敵が持つ攻撃（v72で接続）

既存の `incoming_targets`・`incoming_land` を再利用します。パターン内の追加の敵は同時に出現し、同じ攻撃予定を持つため、個体ごとに予定時刻の配列を複製する必要はありません。既存の `incoming_shots[BP]` で進めた予定の範囲を、まだ生きている個体へ適用できます。

順番はCPUの `BossScript._add_attacks` に従い、個体を先に、各個体の同フレームの複数発をその内側に並べます。発を先にして全個体へ配ると、間隔0や複数発が同じフレームへ入った場合の順番と発射元の記録が変わります。対象選択と実際の受領処理は、既存と同じく期限処理・敵イベントの後です。

最後の発の後の自爆は、武器命中による撃破と異なり、その `begin_frame` が返す死亡イベントに含まれます。退場理由を追加し、発射元を既存の攻撃キューとログの予約欄へ保持します。予約済みの発を、発射元が自爆したことを理由に消しません。

初期化時と最初の時刻0の処理で世界を二重に進める不具合は、実際のCPU部隊計算でも確認しました。v72ではCPU/GPU共通で同一時刻の遷移を一度にする規約を追加しています。詳細は[追加の敵の攻撃](summon-attack-runtime.md)を参照してください。

検証はCPUの実際の `AttackHit` の時刻・並び・発射元と、単純な独立数量を中心にします。被弾数式・盾・遮蔽・戦闘不能は既存の共通検証を再利用し、追加の敵ごとに同じ行列を複製しません。

## 通常攻撃と効果の対象

`enemy_count_above/below` はv73で[フレーム先頭の生存数](world-count-conditions.md)へ接続しました。`target_is_boss/add` はv74で[通知が保持する対象](target-context-runtime.md)へ接続しています。追加の敵の出現元が存在しないことを検証できる通常の世界だけ、従来の定数条件へ特殊化します。通常の召喚受付を開く前に、自律照準の選択結果と予約命中の対象をこの共通文脈へ渡す必要があります。

現在の敵向けバフとダメージの「本体」表現を、追加の敵へそのまま使うことはできません。命中先の識別と世代を、対象選択・効果インスタンス・遅延命中まで保持します。親子の同期発動で別の対象が使われても、親の対象を上書きしない共通フレームを使います。

v80で周期即時効果の実行時対象、v81で即時効果と周期ダメージの[時計の登録管理](timer-registry.md)を共通化しました。次は効果定義単位で残っているダメージ時計を、受領者のキャリアーへ接続する必要があります。同名の再付与は発動者・論理受領者・出現世代も照合し、その受領者の期限と周期だけを更新します。全体付与と単体付与が重なっても、他の受領者の時計を更新しません。別のタイマー実行器を増やさず、登録の捕捉・周期維持・解除後の再生成は共通の規約を使います。

予約命中は文字列の対象名を着弾時に解決し直すだけでは不十分です。捕捉した種類・ID・世代を持つ対象一覧を予約項目へ保持し、コピー・分配でも引き継ぎます。旧世代への攻撃が同じ名前の新世代へ落ちること、対象が消えた攻撃を暗黙に本体へ付け替えることを防ぐ規約を定義し、通常の自動照準からも同じ予約入口を使います。

通常射撃の同時命中には、実際の1回の射撃境界と、どの物体に届くかの明示的な規則が必要です。現在のCPUの追加の敵向けルーティングは、通常射撃を主に照準先1体へ渡します。既存CPUで `multi_hit` が0回だったことをGPU対応の証拠にしません。部位を別の敵と数えたり、すべての追加の敵へ無条件に同じ射撃を配ったりする代用も避けます。

既存の保持対象一覧へ、明示された到達規則で確定した物体の組を集めます。スキルが数える論理的な敵と、物理的な本体・部位は分けます。通常受付を増やすには、実スキルの非ゼロの発動と各受領先への効果を含む部隊計算、通常APIでの検証が必要です。
