# Target-associated hit counters

`target_hit_counter` is a common operation, not a character-name handler. A named
enemy buff carries an explicit `target_counter` descriptor:

```json
{
  "threshold": 100,
  "actor": {"kind": "body", "identity": 0, "generation": 1},
  "families": ["weapon", "skill", "dot"],
  "outcomes": ["damaging"],
  "attackers": "squad",
  "refresh": "reset",
  "on_death": true,
  "world_scope": "single_body"
}
```

Policies have no guessed defaults. Credit is independent of damage, ammunition
and core probability. `attackers` can be `owner` or `squad`; `refresh` can reset
or preserve live progress. An expired or completed instance never donates its
progress to a new lifetime. `on_death: false` cancels the marker without a reward.
Known dead actor generations cannot be rebound. The current death registry has
an explicit 512-handle bound; exceeding it rejects the result.

CPU resources are keyed by carrier UID and refresh epoch; GPU resources also
check the slot's current entry generation. Actor identity includes its own spawn
generation. Every matching counter is advanced and every ready completion is
latched before any child callback. Callbacks run in carrier activation order.
Old completions remain immutable even if children refresh another ready sibling.
Retirement removes only the original UID/epoch, and emits state-end afterward.

Completion listeners use `event:target_counter_complete:<marker name>`. On the
CPU the frozen completion and optional impact live in the nested event frame.
Resource and healing events clear that context. The GPU delivers the same named
completion and snapshots ready records before executing children. No calculation
uses a global last target. Diagnostic last-completion fields are observations.

Body/part landing calls collection before lifesteal and damage accumulation.
Part death follows that part's hit collection before its healing. A threshold
and death cannot grant twice. Skill packets generated by completion callbacks
re-enter the common landing path, including isolated authored stimuli.

The descriptor currently binds a physical actor handle. Logical-enemy component
aggregation, attack-level deduplication and dynamic enemy selection remain separate
world/binding work; they must not be inferred from ammunition events. General
`physical_actor` policies are available for explicit body/live-part scenarios and
authored transport stimuli. Autonomous projectile/shield/add worlds remain rejected.

# Bounded capture data migration

The raw capture recipe now uses the shared counter. The old ammunition-consumption
approximation and global named removal are removed through checked data corrections.
Overflow is authored before the capture increment, so reaching capacity differs
from capturing while already full. Numerical/resource rules remain shared.

The skill text reproduced by [Prydwen](https://www.prydwen.gg/nikke/characters/elegg-boom-and-shock)
describes a target-associated total hit requirement and periodic possession.
[Nikke.gg's demo analysis](https://nikke.gg/elegg-boom-and-shock-early-analysis/)
describes individual damage instances and shotgun pellets. Using weapon, skill
and DoT landing packets is an explicit model interpretation, not our own in-game
measurement. That early analysis also contains conclusions superseded by the
current guide, so it is not treated as a general authority over all mechanics.

This migration admits only one fixed enemy body. Parts, summons, interception,
enemy barriers and vanish worlds are rejected rather than given an assumed
capture policy. CPU and GPU display the model limitation. A 90-second real-data
squad checks capture through capacity and overflow; two further real-data squads
check the six-hit and thirteen-hit burst routes. These establish implementation
parity in the declared model, not full in-game or multi-enemy correctness.
The real-data witnesses use a Fire enemy; the 90-second case observes the Water
element bonus rising by 30.23 points at its configured skill level and verifies
that the source is actually strong against that enemy.

Shared authored quantity cases cover independent credit, families/outcomes,
ownership, actor generation, expiry, reset/preserve, cancellation, siblings and
nested refresh. They are reused by the CPU and GPU verifiers. Opaque allocation
IDs differ between independent runtimes; epoch/behavior witnesses check identity
safety without pretending those IDs have the same numerical value.
