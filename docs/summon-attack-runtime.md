# 追加の敵の攻撃

v72は、追加の敵が持つ攻撃を既存の対象選択と被弾処理へ接続します。個体ごとの攻撃予定配列は作りません。同じパターンの個体は出現時刻・最初の発までの時間・間隔・発数を共有するため、既存のパターンごとの進行位置を使います。命令幅・キャラ入力・敵入力はv71と同じで、世界の最終時刻に8バイトの可変状態を加えます。

世界フレームの先頭で出現と終了を確定し、そのフレームに発射する攻撃を既存のキューへ予約します。個体を外側、同じフレームの各発を内側に並べ、CPUの `BossScript._add_attacks` の順番を保ちます。本体の攻撃と追加の敵の攻撃はパターン宣言順です。照準の選択・乱数・被ダメージは、従来と同じく期限処理と敵イベントの後に既存の被弾実行器が処理します。

最後の発の後に自爆する場合は、そのフレームの敵イベントへ死亡通知を追加します。武器命中による撃破の次フレーム通知とは別のタイミングです。発射済みの攻撃は、発射元が自爆したことを理由に消しません。発射前に撃破・退場した個体は新しい攻撃を予約しません。

明示的な世界フレームを使う診断では、初期化時の時刻0の実行を遅らせ、入力15の最初の時刻0で実行します。世界フレームは時刻0から始め、通常の自律部隊フレームと混ぜません。本体の既存の自律部隊計算は初期化の規約を保ちます。

通常のCPU計算も初期化と最初のループで `begin_frame(0)` を二度呼んでおり、自爆した個体が同じ時刻に次の世代へ入り直す不具合を確認しました。CPUへ共通の `world_frame_runtime` を接続し、GPUにも世界フレームの最終時刻を持たせ、同じ時刻では出現・終了・攻撃予定を進めない規約へ揃えます。元の計算エンジンのファイルを書き換えたり、GPUをその初期化漏れへ合わせたりしません。実際のCPU部隊計算で、自爆攻撃2回の時刻が従来の `[0, 0]` から `[0, 1/60秒]` になることを確認します。

この時刻は各世界に1個の値で、GPUの可変状態はv71から8バイト増えるだけです。個体のHPや予定配列を複製しません。同一時刻中に命中でHPが変わっても、次の世界フレームまで生存数と遷移の判定を再実行しません。現在の生存状態への命中と、フレーム先頭で確定する状態を分けます。

機能確認版を保存してから、次の発の時刻に達していない、または全予定を完了している場合に、個体の一覧へ入らない改善を加えました。127体・120秒・2,032回の実際の被弾を含む5回の中央値は、396.296msから154.089msでした。入力と観測量は同一です。通常の8候補はキャッシュなしの単回比較で6,974.3087msから6,926.1369msで、この差を全体性能の保証には使いません。

攻撃キューにはパターンと設定対象の枠を一つの識別値として保存し、既存ログの予約欄へ発射元を記録します。自爆後も発射元を復元できるよう、生存中の対象一覧から名前を探し直しません。CPUの通常結果でも、追加の敵だけが攻撃する場合の被弾履歴と発射元を出力します。

対象選択と被弾数式は追加の敵用に複製しません。今回の検証は、CPUの実際の `AttackHit` の時刻・順番・発射元と、独立した静止・貫通受領者の数量を比較します。時刻0の自爆と再出現、遅延攻撃前の撃破、本体との同時発射、撃破済みの発射元に大量の未実行予定がある場合を同じ表へ追加しました。盾・遮蔽・回復・戦闘不能等は既存の共通検証を使います。攻撃キューの上限超過も、黙って途中で切らずに結果を拒否します。

通常戦闘の対象振り分けと命中先ごとの状態・効果は未接続です。敵数と本体／追加の敵の条件も、単一本体向けの特殊化から動的な参照へ接続する必要があります。攻撃に付随する敵からのデバフも未対応です。通常の召喚受付と `multi_hit` の受付は引き続き開きません。標準条件の187/203体は、全条件での動作確認済みという意味ではありません。
