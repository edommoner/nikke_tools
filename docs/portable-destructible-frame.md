# 通常スキルFrameから型付き弾への接続

`destructible-frame` は、明示したtyped worldで通常の`burst_cast`通知を送り、既存の発動条件・発動回数・係数確定・mode10スキルFrameを通して弾へ着弾する。計算helperをdriverが直接呼ぶ段階から、共通ディスパッチが効果を選んで呼ぶ段階へ進んだ。新しいダメージ式・イベント実行器・カウンター完了ループは作っていない。

GPUは`PORTABLE_DESTRUCTIBLE_FRAME`で明示的に接続を有効化する。既存mode10の入口と、発動回数消費前の対象確認だけを共通コードへ追加した。型付き着弾・全兄弟の閾値latch・子イベント・破壊終了を、同じFrame配列とwork/depth上限で継続する。helperから`dispatch`を再帰呼出しせず、既存mode26をpushする。各Frameの凍結対象・元Impact・破壊情報は深さ別scratchに置き、同期子の処理後に正確な世代の死亡終了をcollectする。量は攻撃ごとに1回計算し、同じ攻撃の後続対象は子バフで再計算しない。次の攻撃は更新後の量を使う。

CPUはmanager単位のscoped damage callbackを使う。通常の`BuffManager.notify`が効果選択と回数制限を担当し、対象解決へ実worldの生存弾ラベルを渡す。対象0なら発動権を消費しない既存契約を維持する。スコープ終了時は例外時も元のcallbackと対象resolverを正確に戻す。通常の名前付き命中は既存`_notify_frac`と`notify`へ渡す。通常戦闘へ常時適用するglobal patchは追加していない。

Metal26入力（宣言正例17・raw拒否9）と独立sealが成功。元のplain all_projectiles定義のlevel1/10、full burst、DEF0/100、buff失効、係数0/丸め境界に加え、trigger未到来、同時刻2攻撃、発動回数1、対象0で権利保持、名前付き命中の子、128対象/slot127、兄弟閾値→子refresh→破壊のepoch1/2/3を検査した。2攻撃は450→500、名前付き命中の子を含む場合は450→595を既存数値本体で計算する。全typed状態・時計・元Impact・全counter trace・子ATK・実発動回数・root終了後のcontext解放をCPUと比較した。

新経路GPU0.033392秒、readback81,788,928バイト、Runtime163528バイト。成功package `00f3cfbd0d8fbe0c4278bb520d627e0d9439d75ad6f9c0feee61ef4430950d3f`、capture `/tmp/nikke-df-metal26-v3`。旧25入力の入力/native/output指紋と78,643,200バイトを全保持。保存8blockの故障注入は発動数・係数・計算量・子ATK・選択数・contextリーク・拒否statusを検出する。最終固定packageは`a92d846922bc74d7b04dc8f81744eed9cf981c44b8627eb9cc8260ac33821fc2`、CPU51検査/native17成功。

初回Metal23では、mode26を子としてpushする際にready範囲の終端を渡さず、creditが溜まっても完了の子が動かなかった。既存root初期化と同じ終端を既存Frameのvalue引数へ渡して修正し、失敗captureを保持した。独立した実行器へ逃がしたり、期待する子バフを省いて比較を通したりしていない。

従来の通常戦闘492入力も、新しい不変packageでCPU288検査・正本378比較・Metal・独立sealが成功。旧readback1,547,698,176バイトと全バイト一致し、全492の入力/native/output指紋を維持した。変更を無効にした経路ではCUDA/MSLの生成ソースも正規化前のバイト列まで同一。通常Runtime138952は不変。旧goldenを証拠フォルダーへ保持してから、実GPUと独立sealに基づく最新のretention goldenを登録した。新規shader対応を証明するために既存goldenの出力ハッシュを合わせ直したものではない。

通常492のGPU計算は4.483464秒、pipeline作成は65.212706秒だった。生成ソースが同じでも今回のMetal pipeline作成費用は再発しており、恒久的な高速化を主張しない。CUDAのコンパイル入力が同じことは確認できたが、Windowsでの新しいcache hit・GPU数値は今回測定していない。Windows追加実行0、cache claimの削除・付替え0。

歴史fixtureのsourceは変更しない。新しい共通コード2ファイルの完全なbefore/afterを`portable-destructible-frame-source-delta.json`へ固定し、既存と同じ厳密inverseで歴史sourceを検査する。追加のsource変更は拒否する。このinverse検査は新しいGPU計算証明ではなく、新経路26/通常492の実行・独立sealは別に行った。厳密normalizer、ソフトbinary64、保護されたCPU正本は変更していない。
