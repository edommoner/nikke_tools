# 共通の体力層への被弾・ダウン

`gpu/incoming_runtime.slang` を共通イベント実行器へ接続しました。CUDA／Metalは同じ計算・状態・定義・fixtureを使います。今回の受付は**体力層へ到達する攻撃**です。シールド・カバー・分身での吸収、敵の攻撃時計・照準・付随デバフを含む一般のボス戦受付は未接続です。通常画面のGPU受付は開いていません。

## 入力と数値

外部刺激の `op=25` は `[time, 25, 0, 0, targetMask, -1, attack, coefficient]` です。対象は部隊の5bit、攻撃力は0以上1e30以下、係数は0%以上1e6%以下の有限な数値に限ります。入力は攻撃力・係数・明示対象であり、CPUで計算した被ダメージ、途中HP、ダウン状態や通知履歴を受け取りません。初期HP・防御は既存の `environment.allies` を使います。

ダメージは共通binary64で `max(max(attack − finalDefense, 0) × coefficient / 100 × max(1 + receivedDamagePct / 100, 0), 1)` の順に計算します。ダメージを整数へ丸めません。防御と被ダメージ補正は、その受領者へ到達する直前の状態から読み、前の受領者の子効果が後の受領者へ反映されます。数値あふれはstatus 16で拒否します。

味方の `received_dmg_pct` を接続しました。敵への被ダメージ増加と数値IDが同じため、味方専用の属性を梱包して攻撃用の集計から除きます。味方の被ダメージ軽減が自分の与ダメージを減らすことはありません。

queryと最終状態の各 `allies` に `received_damage`、`received_hits`、`down` を追加しました。received_damageは無敵・不屈の適用後に体力層へ入る量の合計で、残りHPを超える分も含みます。received_hitsは生存中に対象となった回数で、無敵で体力ダメージ0になった発も含みます。既にダウンした対象は処理しません。

ABIは `0x5045563C`、入力8,192語・出力20,480語です。検証の追加に合わせ、ホストの単一バッチ上限を512へ拡張しました。258正例・8拒否の266入力を一度のGPU dispatchで検証し、Windowsの短い比較でコンパイル／コンテキスト初期化を繰り返しません。

## 保護マーカーと通知順

`invincible` と `undying` は値の大小ではなく、生きている効果の存在を見ます。値0のマーカーも有効です。通常の期限と無期限passiveの実行時条件を共通の受領者判定で評価します。

1. 無敵なら体力ダメージを0へ制限する。
2. 致死量で、既に不屈があればHP1を残す量へ制限する。
3. なお致死なら `event:lethal_hit` を同期して処理し、そこで得た不屈をこの発へ再適用する。通知の子による回復で現在HPが増えた場合も、更新後のHPで致死を判定する。
4. ダメージを適用する。非致死ならHP通過通知を完了し、その後 `received_hit` を処理する。致死となった発では、HP0への下降通知で救済効果を発火させない。
5. 致死が確定した発は、received_hitの子が回復してもダウンを取り消さない。受領者の片付け後に `event:self_down`、生存者の部隊順に `event:ally_down` を処理する。

この順序は固定CPUのボス被弾モデルを参照したものです。体力層の通知と無敵・不屈の相互作用を移しており、未接続の保護層まで検証したという意味ではありません。

## ダウン時の状態

受けていた補正の本人ぶんを外し、他人へ与えた補正は残します。共通の各効果に有効受領者のmaskを持たせ、部隊全員へ与えた補正を1人のダウンで丸ごと消しません。発動予算は維持し、個人の通知カウンターはリセットします。部隊共通の弾薬消費カウンターは維持します。

武器変更、チャージ、装填待ち、自動補充の予約を終了し、ダウン後の射撃・外部通常攻撃・バースト選択を止めます。個人通知を抑制しますが、self_down、部隊の弾薬消費、既に登録されたtimerは固定モデルに従う別の経路です。登録済みの回復時計が、施術者のダウン後も生存者を回復するケースを検証しています。通常回復はダウン者を復活させません。

復活、`persist_on_revive`、失われたpassiveの復元、動的対象・対象別スタックは未接続です。これらの入力を受け付けるための実装・検証を別途進めます。

## 検証と効率化

新しい28ケースは `tests/fixtures/portable-incoming.json` に保持します。統合258正例・8拒否に加え、2件の武器／バースト接続ケースを除く26ケースは、GPU読み戻し後に固定CPUの防御・被ダメージ補正・HP・通知・knock_down処理を使う体力層参照と照合します。被弾式・通知段階の手書き期待値も共通の合格条件です。CPUの計算結果はGPU入力にしません。

HP関連のCPU参照は合計69ケースです。既存のHP失効時の差異2件は期待値を分けて維持します。APIはダウン後に本人の補正が消え、他人への補正と片付け後の通知が残ること、不正な対象maskの400応答を確認します。単体22件、旧イベント16ケース・拒否2件、203体の効果を除く武器回帰も維持しています。

被弾用定義がない場合に、被ダメージ補正・無敵・不屈の探索を省きました。同じ共通ソースの比較用ビルドと、32定義・64入力・3秒間に30発の体力層攻撃を各3回測定し、入力／全出力ハッシュが一致しました。MetalのGPU時間中央値は8.156msから7.215msへ約11.5%短縮しました。固定した体力層の測定であり、本体全体やボス戦の速度ではありません。

最新CUDA照合状況は `research/portable-combat-checkpoint.json`、前段230ケースの両GPU一致は `portable-combat-v11-checkpoint.json` に固定しています。全キャラ・全特殊効果・実編成・通常画面のGPU接続は未完了です。
