# 共通の敵コード条件

`target_code:` 条件を、CUDA／Metal共通Slangの発動条件・実行時条件へ接続します。実CPUは部隊共通の `BuffManager.state.enemy.code` を読み、ボス／追加敵という現在の照準対象によってコードを選び直しません。未指定・null・空文字の敵コードは条件を通し、指定があれば文字列の完全一致を要求します。空の条件接尾辞、空白、コロン、未知のコード名も同じ比較規則です。大文字小文字変換やtrimはしません。

## 入力と数値

通常の定義入力は `environment.enemy_code`、実編成入力は既存の敵設定 `enemy.code` から渡します。条件を読む定義がある場合だけ、既存の名前IDプールへ条件コードと非空の敵コードを登録します。GPUへ真偽のCPU計算結果を送りません。旧コンパイラーのkind22の事前計算をコピーせず、専用の条件ID44・名前ID＋1・ゼロの数値引数へ変換します。GPU側はkind22を拒否します。

ABIは `0x5045566A`。単語AIM_POLICYの後の未使用の整列余白7ワードを、部隊共通コードID＋1・宣言された名前数・予約ゼロの検査に使います。コード0は未指定、条件名は1〜名前数です。宣言範囲外のID・数値引数・予約bitをGPUでも拒否します。入力86016／出力159744 wordsを維持し、Runtime／Definition／Frameのフィールドや私有配列は追加しません。文字列はCPUでID化し、比較はGPUで行います。既存のbinary64計算とinteger／powの規則は変更しません。

条件の名前IDはbuff・mode等の既存IDと衝突しても同じ完全一致を意味します。ID0の名前も＋1で表し、未指定の0と区別します。条件を使わないプログラムは名前容量や余白を消費しません。名前プールは既存の256件を上限とします。

## 観測した規則と補正

有限時間効果は発動時の条件、永続効果はクエリ時の条件も評価する元CPUの区別を維持します。永続passiveは不成立でも戦闘開始時に登録され、コード条件によって寄与を制限します。有限の条件付きpassiveは、条件が成立し続ける間の期限延長を保持します。

追加敵の対象継承は既存の`hit_count`規則を使います。最初の刺激で使った`on_attack`は対象をボスへ戻すため、コード比較と無関係にボスへ適用されました。刺激を`hit_count`へ訂正し、追加敵の対象と部隊コードの独立性を検査しています。数量やコードの期待値は変えていません。

実編成検証では、180秒終了時にもネオン：ブルーオーシャンの武器変更が有効で、従来の固定編成比較器が停止しました。終了時刻・効果は維持し、実CPUのauto／chargeメソッドが実際に動いている間の射撃方式と、有効モードの定義ID・発数・行動待機時計を観測します。GPU側は実際に渡した静的モード記述子から射撃方式を読み、CPUの途中状態をGPUへ渡しません。モードが無効な旧編成の参照形式は維持します。

## 現在の検証範囲

103の共通ケースをM5と実CPUで照合しています。五つの既知コードに加え、未知名・空白・未指定・空条件、作成者5人、passive／有限効果、回復、照準対象・actor条件の組み合わせを含みます。実編成は全効果・180秒のまま、一致／不一致／未指定×通常／成長の6条件を確認しています。
