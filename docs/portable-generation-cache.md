# CUDA前段のSlang生成キャッシュ

共通CLIの`generation`は、既存sealed packageのCUDA／Metal生成物をCPUだけで準備します。`--generation-cache`は`run`、`compile`、`module-check`でも使えます。NVRTCの`--compile-cache`や保存CUBINの再利用とは別の層です。数値実装・生成オプション・strict normalizer・GPU入力・基準goldenは変更していません。

```sh
python /path/to/package/scripts/nikke_gpu.py generation \
  --out /path/to/fresh-generation \
  --slang-root /path/to/pinned-slang \
  --generation-cache /path/to/slang-generation-cache

python /path/to/package/scripts/nikke_gpu.py generation \
  --out /path/to/fresh-required-generation \
  --slang-root /path/to/pinned-slang \
  --generation-cache /path/to/slang-generation-cache \
  --require-generation-cache
```

Macの独立CPU準備用です。Windowsではこのstandaloneコマンドを拒否し、既存の制限付きJob内の`compile`／`run`／`module-check`だけで生成キャッシュを使います。Windowsの新規検証停止を解除する変更ではありません。生成だけの成功から、CUDAコンパイル・リンク・戦闘・環境保全を認定しません。

対象は両reflectionを持つresident entryです。keyには全GPU source SHA、entry、固定オプション、ホスト、コンパイラ位置とbin／lib／include／share/slangの全ファイル、生成器・ABI／scope監査器のSHAを含めます。documentationは除きます。未知のmodule import、非literal include、時刻macro、外部コンパイラ環境overrideは拒否します。__FILE__を使う場合はsource rootもkeyへ含めます。通常の同一ソースは異なる固定package rootでも再利用できます。

cold生成は別の一時ディレクトリで行い、両reflection・CUDAのsizeof／alignment assertion・scope snapshotを監査します。ソース／コンパイラの再hash後にcacheをpublishし、その読出し結果を再監査してからlive生成物へpublishします。cache hitも同じ監査を行います。欠けたpair、base64／byte数／SHA不一致、変更されたreflectionやABI、required missでは再コンパイルにfallbackしません。cold missの競合は既存の所有権付きclaimを使い、他人のclaimや放棄されたclaimを削除しません。

captureには`generation-cache.json`と両reflectionを保存します。phase journalはSlang subprocessの実際のentered／returnedを記録し、cache receiptの呼出し数と独立照合します。cacheの元ディレクトリやコンパイラ本体を読み直さず、保存captureのgenerated bytes・reflection・receipt・phaseから監査できます。通常GPU／NVRTC監査と保存結果の厳密な比較も維持します。新moduleはreplayの保護対象で、両packageに存在しない旧方式のreplayも維持します。

Macの現行本体114sourceで、初回4.090秒・Slang2回、必須hit0.471秒・Slang0回を測定しました。同じ生成CUDA／Metalが既存sealed基準と一致しています。単一測定でありWindowsの速度や戦闘全体の高速化を意味しません。生成済みcacheを別packageから必須再利用したMetal実編成4入力も成功し、Slang0回・全出力一致と保存結果の独立監査を確認しました。全849をGPUで再実行してはいません。

故障検査11件に加え、既存NVRTC cache・resident build・phase・replay・compile CLI・module・保存CUBINの検査を使っています。今後のCPU smokeにも新11件を必須登録しました。詳細な出所・実測・限界は`research/portable-generation-cache-checkpoint.json`です。cache payload、raw、PTX、CUBIN、個人設定は共有記録へ含めません。
