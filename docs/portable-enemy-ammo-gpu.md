# 共有敵弾薬のGPU接続

`enemy-ammo`は元ヴェルヴェット全76定義を維持し、既存ADD/BODYの発射試行へ明示magazineを接続する専用検証入口。既存CPUの`enemy-ammo-common`6ケースを減らさず、Lv1/Lv10、遅延出現時の空対象、再出現、HP撃破、BODY射撃を同じ元編成で比較する。

割合と固定値の演算は`ammo_instant_numeric.slang`へ切り出し、味方の`applyAmmoInstant`と敵の`applyEnemyAmmoInstant`から同じ関数を呼ぶ。除算→乗算→ties-to-even、signed i64への変換、加算前の飽和、i32下限の拒否は既存のまま。新しい丸め式やCPUで作った結果をGPUへ入力しない。小さな`ammo-instant-numeric`は元の`_register_instant_handlers`から直接得た実ハンドラで705ケースを比較し、raw拒否8を含む713入力がMetal/独立監査で成功した。初版は予期した数値範囲外16をtransport statusに載せたためCLIが失敗。保存readbackの全713演算が一致することを確認し、共通CLIを緩めずprobe内の数値status欄を分けた修正版を別captureでsealした。

新wireはADD実戦prefix116,464wordの後へ静的宣言1,168wordを加える。宣言順128枠と、実actor slotごとのcapacity/initial/cancel_on_full/reload_secondsを持つ。BODY/ADD以外を拒否し、全射撃sourceがmagazineを宣言することをhost/device両方で要求する。CPUの現在残弾、出現時刻、射撃リストはシリアライズしない。

実actor generationが変わった時だけ初期化し、旧世代の残弾・期限は履歴へ保持する。生存と期限を既存frameで読み、due以後の最初のframeで全装填する。配達位置で残弾を減らし、弾切れならリロードを開始し、reload/dead/staleなら既存target queryやRNG・被ダメージを呼ばない。元の射撃試行/counterは進め、後へ再予約しない。これは既存CPUの宣言モデルであり、ゲーム敵の実リロード周期を確定するものではない。

受取順は既存`actorSortSpawnOrder`を使いBODY→生存ADD順。名前付き完了通知は既存`applyDefinitionFrame`から全受取loopの後に一度だけ出る。受取ゼロでも通知を出し、匿名なら出さない。残弾満タンによるreload中断は完了イベントを発行しない。enemy処理を味方5人maskへ置換しない。元ヴェルヴェットが必要とするkind11は、既存のゲージ弾薬消費処理をこの入口だけで許可するguardへ明示登録した。最初の梱包v1はその登録漏れをnative/GPU前に検出し、失敗ログを保存している。

既存2,032,000word出力の未所有tailへ、128slot状態、512世代履歴、2,048件の充填/完了/発射試行/reload receiptを分離する。Runtime構造体は増やさない。共通readbackは旧世代も含む全残弾/期限、対象順、名前付き完了snapshot、発射を通したWS queryだけが存在することを検査し、その後に元の全戦闘比較器へ渡す。

共有source変更は正確なbefore/after逆変換で過去監査へ接続する。numeric関数抽出は旧entryの生成codeを変えるため、以前のguard無効時raw byte保持の証明を今回へ流用しない。旧golden/sourceの再認定は別途必要。生成normalizerと保護CPU4ファイルは変更しない。現時点は44unit、元CPU6ケース、CUDA/MSL生成を確認。初回Metal v2はactor pool初期化でkind11を拒否し全正例status64だった。stage8000/元row2の診断と全readbackを保持しており、成功扱いにしない。修正03ee0078では専用entryからのみ、既存resource op3/実行flag付きkind11をactor/landing受付へ接続する。resource wire/条件/消費・通知の共通validatorとconsumerは維持する。exact inverse ledgerにevent_runtimeの変更前後も追加し、7unit成功。新v5パッケージでCPU6基準を再計算し、修正版のCUDA/MSL生成を確認した。その後の結果は末尾の実M5検証を参照。

容量固定以外の敵武器変更・容量バフ・flat充填・forced reload、self-destruct、攻撃付随debuff、実ゲームの敵弾薬パラメータ、現CUDA実機、default admission、全キャラの認定は残る。満装填による中断branchも今回の元負値効果だけでは実戦発火しないため、元76効果の比較からそのbranchを実証済みとはしない。

## 実M5検証と独立照合

固定0d3bce27 / packet34cbe45dの20入力は全比較成功。元76定義の6戦闘条件と不正wire14件を保持し、全残弾・世代履歴・reload・射撃試行・受取順・完了snapshot・全戦闘/skill履歴を照合した。各条件800件、合計4,800件のresource通知を、元の順序・最終ゲージ値・消費発動回数も含め比較した。従来128件のprefixと既存consumerを保持し、専用entryだけ既存tailへ最大4,096件の続き領域を持つ。129件目の破損と未使用tailを検出する負例を含むunit45件が実packetで成功。

Metal実GPU0.8562025秒、初回pipeline59.394478秒、library1.987327秒。GPU禁止のfresh child監査124.232063秒で全20入力/全出力を再照合しsealした。Runtime stride138,952byteは不変。v2のkind11初期化失敗とv5の128通知上限失敗のraw/claimは保持し、再送や成功への付替えはない。途中v3 compact未対応、v4 native期待値再利用不可、600秒指定の上限違反はすべてGPU/claim前に停止した記録として保持する。

CLI enemy-ammoをsealed通常入口へ更新。enemy-ammo-cache-onlyは同じ計算・goldenにCUBIN/O1・必須compile cache・NVRTC禁止・必須paired generationを適用する。Windows実GPU/キャッシュhitは未確認で、新しいWindows実行依頼は0。共有numeric抽出とresource記録hookによる旧スイートの現source再認定は残件。従来成功証跡を今回sourceへ付替えず、全キャラ/default受付は未認定のまま。証跡はresearch/target-count-query-evidence/enemy-ammo-metal-v1.jsonとtests/fixtures/enemy-ammo-independent-v1.json。
