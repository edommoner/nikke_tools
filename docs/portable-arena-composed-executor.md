# 座標と実射撃groupを持つ共通入口

`coordinate-composed`は、主実行器のfeature chain・GPU常駐Runtimeと、座標frame／選択／保留packet／着弾を同じ入口へ接続するprivate suite。CUDA／Metalは同じSlang入口、生成schema、静的入力、native比較器を使う。別の効果計算やRuntime配列は追加しない。

## 入力・状態・読取り

入力108648wordは既存world104400、group policy8、座標scene3184、area1056から成る。scene開始104408、area開始107592。座標arenaを出力1048576word以降へ置き、groupの元のarena・compact履歴を保持する。出力strideは1310720word（5MiB／入力）。定数は`portable_arena_specs`と生成headerを共有する。

合成入口は`runtimeStates[id]`を既存の初期化・commands・writerへ渡す。旧座標入口は従来のローカルRuntimeを使う。共通hook headerからselector・cast・landingの接続名を登録し、主feature chainは合成rootだけがincludeする。旧入口のinclude閉包に未使用の常駐Runtime宣言が混ざらないよう、両入口のstorage分類も検査する。

Python transportは1.25Mwordの受付を登録済み入口と正確な入力strideへ限定する。合成入口へ旧1Mwordの出力を渡す場合も拒否する。Swiftのサイズ・device最大buffer・uint32アドレス検査、CUDA／MetalのRuntime reflection照合は維持する。保存readbackのブロック監査にも同じ出力形状を追加した。容量と1GiBの保存領域reserveは削らない。

読取器は既存の全battle／skill trace／座標比較器を再利用し、座標arenaだけを旧ビューへ移す。groupのtuple・世代・owner・時刻・packet数・通知数・固定履歴とcompact履歴・解放済みslotも別途照合する。静的packing中はCPUの戦闘・着弾関数を禁止する。

## 正本規約と未対応

座標スキルは選択snapshotを保持し、遅延着弾では対象名を現在世代へ解決する。groupのActorHandleは世代固定で、旧世代を再出現対象へ付け替えない。

合成profileの実射撃groupは現在body-only poolに限る。座標部位／阻止対象を持つpoolで射撃するとstatus64で拒否し、未実装の物理確率・対象選択を素通りさせない。既存座標部位のskill packet／保留／世代交代は接続する。座標モードの通常射撃は部位確率0の観測もbody通知の前に発行する。既存の分数通知関数を使い、0の通知を比較から除外しない。

新97入力は旧88（native75／拒否13）に、座標skillとbody-shot groupが同じフレームで動く6正例と3負例を加えたもの。新正例はowner0／3と、1packet・3散弾・3散弾×2銃口。負例はowner policy、area識別子、scene version。座標部位への物理射撃、手動aim、元定義の混合world、公開受付は今後の接続対象であり、全キャラ対応の完了ではない。

## 失敗を保持して修正した点

初期packageはSwiftの旧サイズ受付でdevice取得前に停止した。別のsandbox内検査はMetal deviceを取得できず停止し、通常環境の読み取りでApple M5を確認した。合成の次版はローカルRuntimeが使われていたため、物理Metal reflectionとSlangの常駐buffer契約が一致せずカーネル実行前に停止した。常駐Runtimeへ接続後の実GPU出力では、旧88はnative一致、新6正例は0の部位通知だけが不足した。比較項目を削らず共通通知へ接続した。

旧座標入口では、条件付きの未使用includeから常駐Runtimeと誤分類される問題もSlang reflectionが検出した。full chainのincludeを合成rootへ移し、共通hookを一つのheaderへ抽出した。reflectionやsourceの検査を緩めていない。

各package・失敗・claim・rawを保持する。source監査は今回の全ファイルのcurrent／baseline全文とSHA、および新header／入口の全SHAを照合した後、過去のledgerをそのまま検査する。生成コードnormalizer、CPU正本、共有binary64、CUDA compile-cacheのidentity規則は変更していない。

検証結果の集約と最終的な未完了項目は、対応checkpointと`docs/mac-handoff.md`を参照する。

## 最終検証

Apple M5の実GPUで新97入力がnative一致（81正例・16拒否）、独立seal済み。GPU時間0.080212秒、cold pipeline90.985秒。旧81と旧88も最終sourceで一致し、入力・出力全byteと生成CUDA／Metalコードを保持した。新97の旧88ビューはworld領域と座標領域が完全一致し、主入口のadmission診断16wordだけは入口の仕様が異なる。新goldenはその診断を含め全出力を固定する。

最終compact packageはCPU42件と制御415件（Windows専用1skip）を通過。full2922→compact1628の残存record／byte／goldenは完全一致。保存rawへの6故障、合成sourceへの6改変、transportへの5改変をそれぞれ拒否した。過去のsource ledgerを除外せず、今回の全文・SHAが一致する場合だけ過去sourceへ逆変換して検査する。

今回のGPU kernel実行は5回（成功4・比較失敗1）。実行前停止4件と容量guard2件も保存し、consumed packageの再試行は0。Windowsは保存objectのread-only確認だけでcompile／GPU実行0。objectは残っているがproof結果JSONも回収receiptもないため、CUDA計算や回収の成功とは扱わない。host sin45の1ULP差に関する数値方針は回答待ち。

失敗rawを含め削除0。終了済みrawをSHA・inode・全byte保持のまま疎ファイル化して容量を回収した。詳細な指紋・package・各失敗と残課題は`research/portable-arena-composed-executor-checkpoint-v1.json`と`research/coordinate-composed-evidence-v1/`に記録する。
