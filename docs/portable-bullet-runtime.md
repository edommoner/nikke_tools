# 受領者別の発数寿命

2026-10-19、ABI `0x50455641`。256定義・512実体・遅延対象cache 1,024枠を保ち、入力49,152語・出力36,864語へ更新しました。`gpu/bullet_runtime.slang` と `gpu/bullet_consume.slang`、既存の実体・対象・数量・武器処理が共通実装です。CUDA／Metalの固有部分は生成コードの起動と読み戻しです。

## 消費と再付与

`duration_bullets` は正の整数1〜2,147,483,647と、寿命を付けない明示値−1を受け付けます。0・小数・bool・範囲外・非戦闘経路の有限発数寿命は拒否します。時間の期限と併用した場合は先に到達した方で終わります。武器変更自体の発数寿命は従来の武器処理に属し、バフ寿命とは別です。

消費は射撃者の物理発射ごとに1回、on_attack・hit_count・full_charge_fire／hit等の通知の後、last_bulletの前です。散弾10粒×銃口2でも1回です。battle_start等で発射と同じ時刻に付いた効果はその射撃では消費せず、共通コンパイラーのbullet-bound timingを持つ効果は消費します。full_chargeとfull_charge_fire／hitの規約も分けています。

各受領者は独立した残り発数とstack overrideを持ちます。非遅延の再付与では対象の残り発数を復元し、未消費ならstack加算、使い切っていれば1から再開します。同じ定義の対象maskが変わっても実体を増やしません。発数寿命を持つ異なる定義は同名でも統合しません。ダウン時は受領者の発数・stackを片付け、送信済みの他の生存者への効果は維持します。

順位対象は最初の参照または消費でGPU解決します。既存CPUの解決済み遅延バフの再付与は、受領者別カウンターを復元せず、別のsource側カウンターを再設定します。この挙動とsource自身の発射によるfallback消費も独立CPU参照で固定しています。通常の辞書型buff／量補正は受領者stackを使い、直接HP・防御・回復やcaster-based attackの後段は既存CPUどおり実体のglobal stackを使います。

同一射撃の消費走査が終わってから全終了対象を削除し、その後に終了通知を実行します。後続行の遅延順位や同名の再生成が削除途中の状態に依存しない順序です。`carriers` から発数・overrideを読み戻し、`bullet_lifetimes.active_carriers` で登録数を確認できます。

## 検証

共通389正例・19拒否がMetalで成功しました。追加36正例中33件を、GPU読み戻し後に実際のCPU CharState／BuffManagerへ照合しています。CPUの発射履歴・途中状態・対象maskはGPU入力にしません。5人までの独立射撃、装填、同時通知・遅延対象、HP・ダウン、定義255、再入可能な終了コールバックを含みます。単体28、既存イベント16＋拒否2、HTTP API、203体の武器のみの射撃、203部隊の装備初期化も回帰確認しました。

発数終了時の最大HP縮小について、CPUがHP 1,500／最大1,000を残す既知不整合を記録し、GPUはHPを1,000へ同期します。既存3件と合わせたHPの既知差異4件を両GPU照合へ含めます。これはCPU値への無条件追随ではなく、別々の期待値で検証する数値設計です。

固定版 `d8d0d79` はWindowsのRTX 3070 Tiでも、通常条件・低優先度の1回を95.711秒で完了しました。389正例・19拒否の共通ソース・入力・全出力・検証コード・statusと、既知差異を含む全CPU参照リストがMetalと一致しました。元のHEAD／作業ツリーは保持し、残存処理はありません。

先行した診断トレース付き実行は120秒で停止し、readbackを得ていません。Macの入力準備のみの比較では、通常0.293秒に対して同じトレース方式は68秒経過でも未完了だったため停止しました。診断負荷を外した通常条件を別に1回実行した経緯と両記録を保存しています。GPU計算の失敗と、この診断条件のタイムアウトを混同しません。今後の短いWindows検証にはグローバルなPythonトレースを加えません。最新の実機照合・固定commitと測定値は `research/portable-combat-checkpoint.json`、正確なWindows要約は `windows-portable-combat-v17.json`、失敗記録は `windows-portable-combat-v17-traced-timeout.json` です。

## 効率化と残る範囲

通常の装備・持続バフを射撃ごとに全走査する代わりに、発数寿命を持つ生存実体だけを登録順のリンクで辿ります。追加・解除は定数時間、再付与は順番を維持します。対照カーネル `benchmark_bullet_scan.slang` は同じゲーム処理を使い、候補選択だけ全走査へ戻します。8プログラム・各256実体、5射撃者の3秒／900物理発射の固定負荷を各3回測定し、入力・全出力SHA-256を照合します。中央値は1,477.970msから1,382.347msへ約6.5%短縮し、入力・全出力が一致しました。通常buffの数値集計など既存処理は同じ負荷に含みます。実編成の全体性能・ピークメモリの証拠とは区別します。

実定義の入力preflightは6体、全効果込みの実編成GPU検証は0/203体です。ランダム／対象リスト、残る特殊効果・保護層・復活・敵世界・操作ポリシー、実編成入力と通常画面、全体性能を引き続き接続します。
