# 共通座標descriptorと対象集合のGPU部品

共通Slangへ座標descriptor、depth／出生時刻／pattern／ordinal順、live世代付き全部位集合を追加した。共通CLI `coordinate-scene` の21入力（正本比較10、不正入力11）がApple M5のMetalで全word一致し、保存結果をGPU再実行なしで独立sealした。同じSlangからCUDAとMetalを生成したが、今回のCUDA実行結果はない。

これはcallerが与えるpool viewと明示open／close／hit／capture操作の部品検証である。戦闘Frame、scheduler、実skill着弾、範囲形状の距離計算への接続は未完了。公開座標GPU受付guardは維持する。

## 検証した境界

127対象、32patternの末尾index31、円と回転矩形のdescriptor、depth反転、同depthの出生時刻反転、pattern順、破壊と再出現の世代、不壊、空集合、signed zeroとsubnormal depthを比較した。入力は正本validateだけでpackし、戦闘simulateや正本geometryから対象一覧を作ってGPU入力へ流していない。対象一覧はGPUで生成する。

kindは部位1とprivate interrupt6を区別し、BODY slot0を対象descriptorへ混ぜない。静的異常は変異前にstatus64で拒否し、出力残部も全zeroを要求する。positive出力32768wordのdescriptor／pool／snapshot／未使用末尾を全比較する。保存rawのdescriptor、世代2か所、末尾の4改変も検出し、原rawのSHAは不変だった。

独立sealとraw SHAはresearch/coordinate-scene-evidence/に記録した。GPU時間は約0.0174秒。新componentはresident reflectionを持たないため、初回のresident generation cache利用はguardで停止した。guardは緩和せず、既存の非cache paired生成で検証した。失敗captureも保存している。

## 正本accountingの訂正

前の座標reference記録にあった「消滅済み対象は空kindを返す」という説明は誤りだった。正本hit_targetはkindを返し、後続packetはpart総量へ計上される一方、消滅したpoolのdealt／hitsは増えない。既存bridge実装はこのaccountingを保持している。25番目の同cast内破壊ケースで、先に捕捉した対象へ届く後続packetとpool更新の差を明示検査した。単体テストの空戻り値は故障注入であり、正本stale動作の証明には使わない。

## 再利用と残件

固定full／compact packageの全payload SHAと残存record一致を検査した。最終packageはcomponent CPU12件、旧mixed81のCPU52件／native68件／入力指紋保持、共通制御392件（Windows専用1skip）、座標reference25件が成功した。GPU実行packageから最終packageへの既存record差はCLI登録・projection・projectionテストだけで、数学、case、比較器、native、shaderは同じ。新goldenは独立sealの出力を採用した。

次はcaller pool viewを共通Frameへ接続し、全部位skillの実着弾を比較する。その後、通常範囲skill向けhypot／radians／sin／cosを設計する。通常弾の確率分布にはacos／atan2／pow、角区間、10点積分、乱数draw契約が別に必要である。既存binary64・正本CPU・strict normalizer・既存world shader／goldenは変更していない。全キャラ認定0、残20分類、通常UI CPU、目標未達を維持する。

Windowsは接続復旧の連絡後もこのMacからhost unavailableとなった。既存PTXの保存結果はunknownで、今回の追加依頼・再実行は0。詳細な固定値とpackage IDはresearch/portable-coordinate-scene-checkpoint.jsonを参照。
