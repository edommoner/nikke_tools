# 攻撃力順の敵選択

`enemies_top_atk:N` をダメージと既に対応している敵バフへ接続します。効果の受領数は1〜256、実際の敵スロットは現在の共通実行器の上限8です。生存している敵を基礎攻撃力の降順で選び、同値なら本体、追加個体の登場順（初期は入力順、再出現は後）とします。照準・現在HP・防御の順位へ置き換えません。既存のCPU BossScriptの選択規約を参照します。

各敵の基礎攻撃力をlittle-endian binary64の2ワードで入力します。本体の省略値はCPUの `DEFAULT_BOSS_ATK`、追加個体は0です。実編成入力でも指定した本体攻撃力を保持します。入力順位・生存対象・発動時計をCPUで計算して渡しません。ABIは `0x5045564D`、追加16ワードは既存の余白に収まり、入出力は各53,248ワードのままです。

GPUが初回または世代変更後の必要時に基礎攻撃力と現在の登場順の順位を作り、8個体を4ビットずつの1ワードへ保持します。対象を選ぶたびに現在の生存状態を調べ、上位N個体だけを返します。複数ヒットの途中で敵が倒れた場合も再選択します。攻撃力の比較は共通のsoftware binary64、登場順は既存のuint番号を使います。Runtimeへ追加する明示フィールドはuint1個で、未使用のプログラムでは並べ替えません。GPU実配置と総メモリの増減は未測定です。

このキャッシュは現在の入力が持つ不変の基礎攻撃力に限ります。現在の再出現コマンドはHP・生存世代を更新し、同じスロットの基礎攻撃力は変更しません。登場順には既存のenemyBirthを使い、再出現でキャッシュを無効化します。将来の敵スケジュールや攻撃力変更を接続する際はこの不変条件も拡張する必要があります。最終攻撃力への敵デバフや未接続の世界制御に対応済みとは扱いません。

整数の精度損失は入力時に拒否します。CPUは本体攻撃力をfloatへ変換しますが、SummonSpecの追加個体は整数を保持するため、参照側で一律にfloatへ変換すると `2**53+1` の順位差を隠します。参照の元の型を保ち、整数入力は範囲内かつbinary64で正確に表せる値に限定します。既にfloatとして入力された値はそのbinary64値を使います。有限・非負・1e30以下の検査、GPU側のNaN／無限大／負値／上限超過／余白検査も行います。この設計修正と中断した検証は `research/portable-enemy-attack-design-correction.json` に記録しています。

追加33ケースは同値順・ゼロ・負ゼロ・subnormal・大きな隣接値・8番目の符号ビット位置・受領数の上限・非生存対象・照準からの独立・途中撃破・分配・複数ヒット・周期通知・各敵バフ・失効・再出現を扱います。22ケースは元のダメージ／BossScript、9ケースは元のBuffManager／ActorRegistryでGPU後に独立参照します。本体の非生存を扱う2ケースは既存の共通アクター契約の手書き期待値です。ネイティブのBossScriptが本体を常在とするため、この2ケースをCPU一致件数へ含めません。
