# 武器変更終了後の通常武器への復帰

固定ソース `a7f478452f7d9c3dbdca97879a2efdf8634c38a9`。CUDA／Metalで同じSlangと定義・fixtureを使い、ABI `0x50455660` と入出力77824／90112ワードを維持しています。

## 原因と修正

発数によるモード終了時に、共通実行器はその時刻で弾倉と射撃時計を通常武器へ戻していました。しかし、通常武器が実際に再開するのは次のフレームです。その最初のフレームで時計を更新しないと、直前のモードの終了時刻を基準に次弾を予約し、CPU本体より早く撃つ場合がありました。

既存の `physicalModeIndex` に復帰待ちを示す内部値 `-2` を持たせ、最初の通常武器フレームで時計を現在時刻へ合わせます。終了通知の前に補充した弾倉は再補充せず、子通知で変更された残弾を保持します。子が新しいモードへ入れば、そのモードの新しいセッションを優先します。新しい配列・スカラー・wire領域は追加していません。

別の差分は、機械fixtureの入力準備が変更武器の装填時間の省略値を実キャラの仮名用メタデータから継承し、CPU参照はfixtureの通常武器から継承していたためです。`compile_case` の仮名用メタデータへfixtureの通常武器の装填時間を渡し、両者が同じ入力を解釈するようにしました。CPUの戦闘状態や発射履歴はGPU入力へ渡しません。省略時・明示上書き・元のメタデータの不変性・CPU tickを呼ばないことを単体検査しています。

## 残る範囲

`mode-toggle-end-child-reentry` と `mode-replacement-first-shot-coefficient` のCPU raw observer差分は残っています。CPUがモードの有無だけでセッション初期化を判定するため、同じフレーム内の終了・再入や別モードへの置換で古いセッションの発数・残弾を引き継ぐ経路です。既知の `mode-expiry-end-child-starts-fresh-session` と合わせ、新しいモードで弾倉・チャージを継承しない共通契約とCPU互換層の実行順序を引き続き調べます。未解決の差分をCPU完全一致へ読み替えず、GPUを古い持ち越し動作へ変更していません。
