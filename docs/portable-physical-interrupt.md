# 共通実行器の物理interrupt追加着弾

非座標の物理武器を、既存の共通interrupt groupへ接続しました。スキルと物理でHP・score・通知・対象別extra・総ダメージ外累計・吸血の実装を分けていません。通常UI、canonical CPU、legacy CUDA、数値のsoftware binary64とstrict normalizerは変更していません。

interrupt sourceがあるfull worldでは、武器の生成時statsから本体・部位・interruptの値を一度に保持します。物理pierce／armor markerを反映してから必要な射程を取得し、pelletで割った係数、charge、通常／武器変更skill formula、critical／rangeを同じ取得値へ適用します。部位とinterruptは取得済みno-core因子を使い、intercept補正は部位補正のない加算層へ一度だけ加えます。コア・部位の比から逆算したり、pellet通知・回復通知後に値を取り直したりしません。

既存の5人×8word physical shot領域を使い、word0／1にpart／interrupt reach、2..3／4..5に各生成済みbinary64を保持します。Runtime、RootParams、2048件のskill receipt容量は増やしていません。interruptがない経路と、新しい実行器を持たない旧tierは元の生成手順を維持します。旧tierの未接続interrupt着弾は拒否を維持します。

物理の既存ゲート・敵対象・counter・本体吸血を通った後で、部位群、interrupt群の順に実行します。addに入ったpelletにはbody追加着弾を付けず、addが倒れて後続pelletがbodyへ入った場合はその時点の対象へ追加します。全interruptのHP／破壊処理後に既存の吸血／共有回復を呼び、キャラtotal・scoredDamage・typed impact／counter・direct hits／landed・ゲージへinterrupt分を加えません。

`parts-skill-world`は63入力（native59／拒否4）です。従来の物理拒否1件を、整合したCDN metadataとliteral周期を持つ複数発射ケースへ置き換えました。新しい17入力ではRL・AR・SR・SG、散弾と2銃口、通知後の次ショット射程／倍率、回復子でのbuff変更、複数破壊・score、壊れない対象、消失gate、addの最初のpelletでの破壊、射程なし、100%-1e-9の直前／一致、コア・確定critical・intercept倍率を比較します。残る拒否4はdeferred参照制約1とActor偽装3です。

初回60入力ではRLのliteral最小周期・発射後待機とnativeのCDN由来の待機が一致していませんでした。本体発射数がnative1・GPU3となり、interruptも6対18でした。元入力・raw・失敗claimを保持し、canonical CPUやGPUを誤った期待値へ合わせる変更は行っていません。DOWN_Charge＋fire_stance_hold0・待機0・最小周期＝intervalを明示した入力で、元の物理ケースは2発射・12pelletを照合します。短いRL入力でもmanual-control状態まで一致します。

初回849回帰は、GPU実行用のcache環境が最小fake backendのCPU検査へ漏れ、GPU起動前に停止しました。CPU test workerだけからgeneration cacheの選択2変数を除き、cache testは各自で設定を明示します。実際のGPU／compiler childへの設定は維持し、その分離を故障検査へ追加しました。CPU失敗を成功やGPU proofとして扱っていません。

武器phase監査とDefinition view監査は、新しいhookの正確な有限逆変換と5sourceのSHAだけを追加し、元のtoken fixtureを保持します。生成物のnormalizerに例外は追加していません。最終Metalとsource-only paired generation、既存raw保持、生成cache再利用の記録は`research/portable-physical-interrupt-checkpoint.json`へまとめます。

座標着弾、deferred burstの参照モデル制約、random周期の最終tick境界、実CUDA・環境保全、全キャラ認定は未完了です。Windowsの新規実行停止は維持します。
